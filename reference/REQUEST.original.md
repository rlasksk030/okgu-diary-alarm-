[1. 목적과 확정된 방향]

나는 초등학교 6학년 담임이며 학생 13명과 현재 옥구 다이어리를 한 달간 실제로 사용해야 합니다.

현재 앱은 너무 느립니다. Apps Script 최적화는 이전에 해봤지만 효과가 작았습니다. 따라서 Apps Script 내부를 다시 최적화하는 것을 주된 해결책으로 삼지 마세요.

목표는 다음과 같습니다.
- 현재 옥구 다이어리의 화면, 디자인, 기능, 사용 방법을 유지한다.
- 로그인·저장·조회·사진 업로드 등 사용자가 기다리는 주요 처리에서 Apps Script 의존성을 제거한다.
- 기존 학생 계정, 일기, 사진, 댓글과 공개 범위를 보존한다.
- 학생 13명이 동시에 사용해도 원활하게 동작하도록 한다.
- 가능하면 현재 접속 주소와 설치된 PWA의 정체성을 유지한다.

Supabase 사용은 필수가 아닙니다. 실제 구현 상태, 이전 작업량, 응답 속도, 비용, 관리 편의성을 기준으로 적절한 서버·데이터베이스·사진 저장소를 선택하세요.

별도 개발 중인 ‘하루의 행간’을 완성하는 작업이 아닙니다. 현재 ‘옥구 다이어리’의 속도 개선이 이번 작업의 범위입니다.

- 일부 작성자 조회 함수는 시트 전체를 읽은 뒤 ID를 찾는다.

위 내용은 개선 후보이지 측정으로 확정된 병목은 아닙니다. 실제 호출 경로와 소요 시간을 확인하세요.

[7. 성능 구현 원칙]

- 로그인·저장·조회·사진 업로드 요청이 Apps Script를 경유하지 않게 한다.
- 사진을 작은 Base64 조각으로 나눠 Apps Script로 보내는 구조를 제거한다.
- 선택한 저장소의 적절한 직접 업로드 방식이나 서버 업로드 방식을 사용한다.
- 사진 크기 조절, 썸네일, 필요한 시점의 이미지 로딩을 검토한다.
- 목록은 필요한 범위만 조회하고 검색·통계는 전체 기록 다운로드에 의존하지 않도록 한다.
- 중복 요청을 합치고 동일 요청의 동시 실행을 줄인다.
- 대시보드는 필요한 데이터를 효율적으로 조회한다.
- 저장 후 필요한 데이터만 갱신한다.
- 저장 성공은 실제 서버 저장이 확인된 뒤 표시한다.
- 저장 실패 시 작성 내용과 첨부 상태를 보존한다.
- 재시도·저장 버튼 중복 클릭으로 기록이 중복 생성되지 않게 한다.
- 여러 기기에서 수정할 때 조용히 덮어쓰는 문제가 없도록 한다.
- 사용자별 캐시가 계정 전환 시 섞이지 않도록 한다.

밤 10시 알림은 한국 시간 기준으로 유지하세요. 새 서버에서 일기를 저장한 뒤에도 예전 시트를 기준으로 미작성 여부를 판단하는 오류가 생기지 않게 하세요.

[8. 계정과 공개 범위]

학생 일기를 다루므로 기존 공개 범위가 이전 과정에서 달라지면 안 됩니다.

- 나만 보기: 작성 학생만 접근
- 선생님 공유: 작성 학생과 해당 학급 교사
- 게시판 공유: 기존 앱에서 허용하던 학급 구성원
- 사진 접근 권한도 연결된 일기와 동일하게 적용
- 교사 상담 메모와 관리 데이터는 교사에게만 허용
- 브라우저가 전달한 이름이나 역할만으로 권한을 부여하지 않음
- PIN은 앞자리 0을 보존하고 평문으로 노출하거나 로그에 남기지 않음
- 기존 PIN 해시 형식을 확인해 유지·전환 방법을 정함
- 서비스 비밀키나 DB 관리자 키를 화면 코드에 포함하지 않음
- 기존 이름·PIN 입력 UX를 유지하되 새 서버에 맞는 인증과 세션을 구현

현재 코드에서 권한 누락을 발견하면 새 구조에서 수정하고, 수정 내용과 사용자에게 미치는 영향을 보고하세요.

[9. 기존 자료 이전]

과거 문서에는 Code.gs의 열 구조와 실제 시트 헤더가 달랐다는 기록이 있습니다. 과거 문서만 보고 열 위치를 확정하지 마세요.

- 현재 서버 코드와 실제 데이터 형식을 대조한다.
- 먼저 필요한 스키마·헤더·최소 샘플을 확인한다.
- 학생 ID, 일기 ID, 댓글·답글 관계, 사진 연결, 날짜, 공개 범위를 보존한다.
- 이름만으로 계정을 잘못 합치지 않는다.
- 실제 자료 반입 전에 가상 자료로 이전 도구를 검증한다.
- 이전 도구를 재실행해도 중복이 생기지 않게 한다.
- 원본 백업과 이전 전후 건수·관계·본문·사진 대조를 준비한다.
- 실제 학생 본문·PIN·토큰·사진을 GitHub나 공개 로그에 올리지 않는다.
- 최종 전환 직전 추가된 기록도 반영한다.
- 이전 중 쓰기를 잠깐 제한해야 한다면 시간과 절차를 미리 제시한다.
- 전환 후 새로 작성한 기록을 보존하면서 되돌릴 수 있도록 복귀 절차를 만든다.
- 원본 시트·사진·계정을 삭제하지 않는다.

현재 원본 접근이 없더라도 이전 도구, 가상 검증, 자료 형식 검증은 계속 진행하세요.
