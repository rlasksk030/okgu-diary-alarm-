# 알림 후 글 누락 — 2026-10-04 조사·수정

운영 복구 미완료. 원본 시트 읽기는 성공했지만 현재 환경에서 Cloudflare/Pages 직접 요청은 네트워크 정책의 CONNECT 403으로 차단됐다. Cloudflare 비밀값/계정 연결도 없다. 현재 GAS 배포 코드·실행 기록·실제 수신 알림의 링크를 확인하지 못했으므로 발송 주체를 확정하지 않는다.

## 확인한 사실

- 운영 GitHub `main` 기준은 `80400cdbf248b228527fd25717afcd84e4f15844`이며 전환 커밋 시각은 2026-10-04 12:23:36 KST다. 현재 공개 소스의 config/rpc는 `okgu-diary-api.rlasksk030.workers.dev`만 조회·저장한다. 실제 Pages 응답 bytes와의 대조는 차단됐다.
- 연결된 Google Sheets에서 같은 날 **17:15:07, 17:23:14 KST** 저장시간의 일기 2건을 확인했다. 시트에 본문이 보존돼 있다. 두 건 모두 선생님 열람 가능/나만보기 아님, 사진 목록 `[]`. 관련 선생님댓글·게시판댓글·게시판을 ID로 조회해 일치 0건. 알림 대상이 어느 글인지 아직 사용자 확인이 필요하다.
- 제공됐던 GAS 코드의 `saveEntry`는 시트 저장 다음 `_notifyTeachersOfChange_` → `_callPushServer` → 기존 Vercel `/api/send-push`로 호출한다. 현재 GAS에서 이 버전이 실행 중이라는 증거는 아니다. Cloudflare 코드도 같은 알림 문구를 사용하므로 수신 문구만으로 경로를 구분할 수 없다.
- D1의 같은 legacy ID, push_jobs/push_delivery 기록 및 Worker 설정을 읽지 못했다. 따라서 **GAS에만 존재** 또는 **Cloudflare 필터/캐시만의 문제**로 확정하지 않았다.
- 기존 feed SQL은 교사에게 같은 학급의 `teacher` 글을 허용하고 private/deleted를 차단하며 updated_at 내림차순으로 조회한다. API/rpc는 no-store다. 확인 없이 공개 범위를 넓히거나 필터를 제거하지 않았다.

실제 본문·ID·이름은 Git/문서에 포함하지 않았다. 두 후보의 원문은 이 작업 환경의 `.local/incident/candidates.private.json`(0700 디렉터리, 0600 파일)에만 있다. Google 시트는 수정하지 않았다.

## 준비한 수정

- 예전 GAS ID로 조회한 글을 canonical ID로 바꿔 표시한다. 요청 중 다른 알림이 도착하면 최신 대상으로 이어서 조회하며, 실패한 링크는 재시도를 위해 유지한다. 로그인 전 전달된 링크도 주소에 남긴다.
- 알림 클릭 시 기존 창이 처리했다는 응답을 확인한다. 구버전 창이 응답하지 않거나 작성 중이면 원래 창을 유지하고 대상 링크를 새 창으로 연다. 다른 앱 창 이동·강제 새로고침·skipWaiting·전체 캐시 삭제 없음.
- `app-release.json`을 복귀/주기/저장 직전에 no-store로 확인한다. 오래된 버전·잘못된 API 주소는 쓰기를 멈추며 최신 자산은 버전 쿼리로 가져온다. 보이는 교사 피드는 재조회하되 입력 중인 댓글은 건드리지 않는다.
- 사용자가 업데이트를 누르면 IndexedDB 트랜잭션 완료 후 이동한다. 본문·한줄·공개 범위·사진/Blob·수정 ID/버전·입력 중인 댓글 등을 동일한 검증 계정에 복구한다. 저장/사진 처리 중, 보관 실패, 보관 중 추가 편집 시 이동하지 않는다.
- Worker에 선택적인 `MIN_CLIENT_VERSION` 쓰기 장벽과 `X-OKGU-Client` CORS 지원을 추가했다. 읽기·로그아웃은 유지한다.
- 현재 관측한 **사진·댓글 없는 교사/개인 글 1건**만 추가하는 도구를 만들었다. 기존 D1 글(삭제 상태 포함)은 보존하며 UPDATE/REPLACE/삭제·PIN/계정 변경·푸시 발송을 하지 않는다. stable 계정 매핑을 검사하고 단일 INSERT 후 값을 대조한다. 사진/댓글/공개 게시판 관계가 생기면 자동 반입을 거절한다. 기존 전체 이전 도구를 재실행하지 않는다.
- 기존 배포에 적용할 GAS 쓰기·발송 차단 후보 생성기: [로컬 HTML 도구](../migration/source/prepare-cutover-offline.html), [CLI](../scripts/prepare-gas-cutover-guard.mjs). 조회/내보내기는 유지하며 실제 배포는 하지 않았다.

## 직접 접근이 열리면 실행할 최소 절차

1. 알림 링크 또는 위 두 저장시각으로 대상 1건을 확정한다. 클라우드 환경에 `api.cloudflare.com`, `okgu-diary-api.rlasksk030.workers.dev`, `rlasksk030.github.io`를 허용하고 기존 운영 계정의 `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`를 비밀값으로 연결한다. 토큰을 채팅/Git에 넣지 않는다. D1 조회·해당 글 추가와 Worker 배포에 필요한 기존 범위만 사용한다.
2. read-only: `node --use-env-proxy --import tsx scripts/recover-incident-entry.mjs`로 두 후보의 D1 존재 여부만 확인한다. 해당 알림 시간·ID의 push job/delivery 상태와 Worker 설정을 대조하고, 필요한 경우 GAS 소유자가 해당 시각 `saveEntry`/발송 실행 기록과 활성 배포 버전을 확인한다. 시트의 알림 행 부재를 미발송 증거로 쓰지 않는다.
3. D1에 있으면 기존 글을 수정하지 않고 해당 교사 세션의 `getEntry` 및 피드/화면을 비교한다. 없으면 대상 원문과 관련 댓글·사진을 다시 읽어 현재도 이 작은 계획과 일치하는지 확인한다. 기존 migration_records로 author UUID를 확인한 후 아래 단건 명령만 실행한다. source에 새 사진/댓글이 생겼으면 해당 관계만 별도 추가 계획으로 확장한다.

   ```sh
   node --use-env-proxy --import tsx scripts/recover-incident-entry.mjs --apply --key <inspect의_대상_hash> --author-id <검증된_계정_UUID> --source-rechecked
   ```

4. GAS 소유자는 **현재 활성 배포 Code.gs**를 로컬 HTML 도구에 넣고 후보를 검토한다. 원본을 보존한 채 기존 웹 앱 배포의 **새 버전**으로 적용하고, 프로젝트 설정 → 스크립트 속성에 `OKGU_CLOUDFLARE_ONLY=yes`를 설정한다. 새 배포 URL을 만들면 이미 열린 구버전의 주소가 살아 있으므로 반드시 기존 배포를 갱신한다. 진행 중 저장/발송 종료를 확인한 후 대상 글을 다시 읽는다. 기존 트리거 목록은 보존하고 기존 예약을 끌 때 실제 새 발송 담당 설정부터 대조한다. 복구 과정에서는 실제 푸시 시험 발송을 하지 않는다.
5. Worker 수정(CORS 포함)을 먼저 배포하고, 기존 Pages에 수정된 정적 파일을 함께 게시한다. 실제 새 버전의 저장·조회가 확인된 뒤 현재 운영 바인딩을 유지하면서 `MIN_CLIENT_VERSION=cf-20261004-recovery`를 설정한다. 프런트만 먼저 올리면 기존 Worker CORS가 새 헤더를 거절하므로 순서를 지킨다. `.local` 및 localhost용 `trial-web`은 게시하지 않는다.
6. 실제 교사 피드/알림 URL/관련 사진·댓글을 확인한다. 이전부터 열린 GAS 화면은 새 자바스크립트를 소급 적용할 수 없다. 그 화면의 작성 내용은 먼저 별도 보관하고 업데이트한다. 새 보존 기능은 수정 버전부터 적용된다. 기존 설치 PWA·실물 폰에서의 수신/업데이트는 별도 확인해야 한다.
