## 사용자가 직접 할 GAS 설정 — 이유와 클릭 순서

Google 연결 환경이 위 1단계의 **최종 수집·ZIP 전달 가능**을 확인한 뒤 진행합니다. 최종 ZIP 전달이 안 된다면 쓰기를 끄지 않습니다. API 준비 완료는 기존 학생용 화면 전환 완료가 아닙니다.

### 1. 현재 코드와 기존 배포·예약 정보 확인

원본 운영 시트 **확장 프로그램 → Apps Script** 또는 [Apps Script](https://script.google.com/home)의 기존 운영 서버 프로젝트 → **배포 → 배포 관리 → 현재 사용 중인 웹 앱**에서 버전 번호를 확인합니다. 코드가 처음 제공한 서버와 같은지 확인합니다. 프로젝트 최신 코드와 활성 배포 코드가 다르면 먼저 같은 버전을 확보합니다.

**트리거**의 `scheduledDiaryReminderPush` 행 오른쪽 **⋮ → 수정**에서 예약 시간·개수를 확인하고 취소로 닫습니다. **프로젝트 설정**의 시간대, **실행**의 최근 미작성 알림 시각·완료/실패를 기록합니다. 화면에 비밀값이 보이면 스크린샷을 보내지 말고 값 없이 상태만 적습니다. 이것은 중복 발송을 막는 데 필요합니다. 직접 조회할 수 있으면 연결 환경이 대신 기록하고 같은 정보를 다시 요구하지 않습니다.

### 2. 비밀값을 밖으로 보내지 않고 쓰기 차단 코드 생성

[오프라인 생성 도구](https://github.com/rlasksk030/okgu-diary-alarm-/blob/codex/2026-10-02-okgu-speed/migration/source/prepare-freeze-offline.html) → **Download raw file**로 HTML을 다운로드합니다. Chrome **⌘O/Ctrl+O**로 그 파일을 엽니다. 외부 서버로 코드를 보내지 않는 로컬 도구입니다. 사용자 Chrome의 실제 로컬 실행은 아직 확인하지 못했으며 관리형 Codex Chrome은 file URL이 차단돼 가로챈 화면에서 검증했습니다.

Apps Script **편집기 → 원본 Code.gs → 전체 선택/복사** → 도구의 **현재 운영 서버 원본 코드**에 붙여 넣기 → **차단 코드 생성**. 상태에 원본 SHA256가 나옵니다. 제공 코드와 줄바꿈만 정규화한 fingerprint는 `8f4f9b1ba0d650b96e1c6a929a4e569a1c33d8200c8b8895878c4545e785c957`입니다. 다르면 코드를 적용하지 말고 현재 버전이 다르다는 상태만 전달합니다. 이미 받은 동일 코드를 다시 요구하지 않습니다. 실제 다른 버전일 때만 그 버전을 비공개 파일로 검토합니다.

원본 Code.gs는 소유자 기기에 별도 저장하거나 **비공개 코드 파일 다운로드**로 차단 후보도 보관합니다. **생성 코드** 입력칸 전체 선택/복사 → Code.gs 전체를 그 코드로 교체 → **프로젝트 저장**. 원본 상수/비밀값은 바꾸지 않습니다. 생성 도구에 표시된 **원본 SHA256와 차단 코드 SHA256** 및 실제 새 배포 버전을 journal에 기록합니다. 이는 차단 검사만 추가된 버전임을 대조하여 시트 열 대응 검토를 유지하기 위해 필요합니다. 28개 저장·계정·사진·푸시/Sheet 진입점 앞에 속성 검사만 넣습니다. 원본/트리거를 삭제하지 않습니다. 도구 자체는 배포나 동결을 실행하지 않습니다.

### 3. 기존 URL 그대로 차단 버전 배포 → 동결 → 진행 중 요청 종료

**배포 → 배포 관리 → 사용 중인 웹 앱 → 수정(연필) → 버전: 새 버전 → 배포**. 실행 사용자/접근 권한/배포 ID와 기존 `/exec` URL을 유지합니다. **새 배포**로 다른 URL을 만들면 오래 열린 학생 앱이 원래 URL에 계속 저장할 수 있으므로 사용하지 않습니다. 배포 전 각 탭의 작성 본문을 별도로 복사하고 원본 사진을 기기에 보관합니다. 작성/사진 업로드 중인 탭을 닫거나 새로고침하지 않습니다.

최종 수집 담당이 대기 중인 것을 확인한 뒤 **프로젝트 설정 → 스크립트 속성 → 스크립트 속성 추가/수정**에서 이름 `OKGU_WRITE_PAUSED`, 값 `yes` → **스크립트 속성 저장**. 속성만 설정하고 차단 코드가 없는 상태는 동결이 아닙니다.

이후 **트리거 → 기존 scheduledDiaryReminderPush 행 ⋮ → 삭제**로 기존 예약만 중지합니다. 코드·원본은 보존하고 앞서 기록한 설정으로 복구 가능합니다. 속성을 켠 시각과 예약을 끈 시각을 기록합니다. 진행 중 발송이 자동 취소되는 것으로 판단하지 않습니다.

**실행 → 실행 상태**에서 기존 저장·수정·삭제·사진·알림 실행이 진행 중인지 확인하고 완료/실패로 끝날 때까지 기다립니다. 원본 시트·사진을 직접 편집하는 사용자도 이 동안 중단합니다. 상태가 확인되지 않으면 최종 캡처를 진행하지 않습니다.

이 대화에 **“차단 버전 N 배포, 속성 yes, 예약 OFF, 진행 중 실행 종료 확인”**과 시각(한국시간)을 전달합니다. Codex가 이미 확보한 기존 RPC URL에 빈 입력만 보내 저장/사진 진입점 차단 응답을 확인합니다. PIN/본문/계정명 없이 검사하며 정상 저장을 만들지 않습니다. 연결 환경에도 차단 확인을 전달한 후 지시문 3단계로 **최종 A/B 묶음 ZIP을 한 번** 받습니다.

### 4. 최종 ZIP 첨부 이후

최종 ZIP 전체를 이 대화에 비공개 첨부합니다. 누락 없이 B의 자료·계정/PIN·사진/관계를 확인하고 잠긴 새 운영 서버로 반입합니다. 전체 값 대조/복원·권한·피드 검증을 통과하면 이미 승인된 main/기존 Pages 전환과 쓰기 재개를 진행합니다. **원본 시트/사진/GAS 코드 삭제, Supabase/유료 설정 변경은 하지 않습니다.** 옛 GAS 오류 미확정 자체로 전환을 막지 않습니다. 신규 자료를 포함한 D1/R2 복구 방식을 유지합니다.

Google 연결 환경이 최종 ZIP 생성만 지원하지 못한다면 같은 지시문의 대체 경로로 기존 [ReadOnlyOperationalExport.gs](https://github.com/rlasksk030/okgu-diary-alarm-/blob/codex/2026-10-02-okgu-speed/migration/source/ReadOnlyOperationalExport.gs)를 **기존 운영 프로젝트의 새 스크립트 파일**에 추가합니다. Code.gs는 차단 버전 그대로 보존합니다. `backupOkguWithKnownSource → 실행`을 완료될 때까지 반복해 A, 완료 후 `startNewOkguBackup → 실행` 및 `backupOkguWithKnownSource` 반복으로 B를 만듭니다. 이 helper는 getSheet 대신 원본을 직접 읽으므로 동결 중에도 백업할 수 있습니다. Drive에서 새 A/B 폴더 두 개를 **⌘/Ctrl을 누르고 함께 선택 → 우클릭 → 다운로드**하면 한 ZIP으로 받습니다. 같은 원본 ID를 다시 입력할 필요가 없습니다. 이 대체 경로도 실행/ZIP 전달 가능을 확인하기 전 동결하지 않습니다. 사진·상태 확인과 권한 승인 메뉴는 이전 실행 문서에 있습니다. 실패한 연결/백업을 반복하라는 뜻은 아닙니다.

실제 최종 자료와 설정 확인은 아직 없으므로 지금 동결/전환이 끝났다고 보고하지 않습니다. 새 예약은 옛 예약 OFF/진행 중 발송 종료 확인 뒤에만 사용합니다. 같은 한국 날짜에 옛22시 발송이 완료됐거나 불명확하면 그날 새 전체 알림을 억제합니다. 선생님 기기1건은 실제 기기를 특정한 뒤만 발송합니다.
