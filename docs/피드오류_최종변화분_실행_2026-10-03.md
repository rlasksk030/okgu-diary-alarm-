# 교사 피드 오류와 최종 변화분 확보 — 2026-10-03

이 문서와 인계 최상단이 과거 상태보다 우선한다. 실제 자료 이전·main/기존 Pages·운영 알림 전환 승인은 유효하다. 로그인 p95 3.64초 및 최신 D1/R2를 보존하는 복구 방식 수용도 유지한다. 재승인하지 않는다. Paid·Supabase 변경·원본 삭제 금지.

## 현재 결론과 실제 근거

사용자는 해당 일기가 비공개가 아니며 운영 Google 시트에 존재한다고 직접 확인했다. 이어서 교사 화면이 **피드를 불러오지 못하는 상태**라고 밝혔다. 전체 요청 실패이므로 단순 날짜 필터/새로고침 문제로 해결됐다고 판단하지 않는다. 해당 새 일기는 원본에 보존돼 있지만 작업자가 직접 읽거나 Cloudflare로 이전하지 않았다.

현재 공개 GitHub Pages의 로그인·저장·교사 조회는 기존 GAS다. 활동 푸시는 기존 Vercel 연결이며 알림 클릭은 기존 github.io이다. 운영 Cloudflare API는 미배포, 시험 D1은 가상 자료만이다. 학생 기록이 새 서버와 옛 서버에 분산됐다고 단정하지 않는다.

이번 직접 확인:

- 알려진 GAS URL에 **빈 토큰만** 사용한 일반 `verifyToken`/`getRecentEntries` 읽기 요청: HTTP200, 정상 JSONP, 각각 E_AUTH/빈 배열. 함수가 없거나 GAS 경로 전체가 끊겼다는 가설은 확인되지 않았다. 보호된 교사 조회를 우회하지 않았다.
- 첨부한 실제 19:53 백업과 제공 서버 코드로 격리 재현: 교사 피드 13행 반환, 날짜 13개 모두 YYYY-MM-DD, 원본 변경 시도0. **현재 운영 배포/최신 셀/유효한 교사 세션 응답의 검증은 아니다.**
- 운영 main의 `loadFeed`는 이전 요청 중 재조회 요청을 버렸다. 이전 응답이 나중에 표시될 수 있는 문제를 VM과 Chromium에서 재현했다. 작업 브랜치에서는 재조회 요청을 합쳐 최신 페이지를 다시 읽고, 이전 사용자/이전 응답 표시를 막는다. 잘못된 응답과 빈 목록을 구분하며 빈 GAS 응답의 교사 인증도 확인한다. 추가 페이지 실패 후 재시도를 복원한다.
- 실제 Cloudflare 가상 시험 앱에서 **이전 응답 확보 → 학생 새 글 저장 → 진행 중 교사 재조회 → 최신 글 표시**, 조회 실패/재시도 성공을 확인했다. 가상 확인용 글은 삭제했다. GAS 요청0, 실제 푸시0. 숨겨진 일기 입력칸 값의 보존 검사도 했으나 학생 작성 화면/실물 휴대전화 검증이라고 보고하지 않는다.
- 별도 시험 화면의 로그인 CORS 오류도 확인했다. 새 셸에서 배포할 때 `WEB_ORIGINS`가 빈 값이 되는 배포 설정 문제다. 정확한 API/시험 화면 두 origin을 기본으로 복원하고 회귀 검사를 추가했다. **운영 GAS 피드 오류와 별개다.** API 시험 버전 `868a2faf-4fba-4e2e-a025-ad5c0328e9ee`, 별도 화면 버전 `9fd4bc16-87e7-45e2-af4a-e9cace4db877`.

운영 교사 오류의 직접 원인은 아직 미확정이다. 운영 main/Pages에는 수정본을 반영하지 않았다. 실제 오류 응답과 최신 원본을 확보하기 전 운영 전환이나 해결 완료로 보고하지 않는다. 디자인·메뉴·버튼 배치·PIN 강도·권한은 변경하지 않았다.

## 현재 직접 접근 확인

현재 Codex 환경의 Drive/Sheets 연결0, Google outbound identity0, 공유된 사용자 Chrome/OAuth 도구 없음. 클라우드 Chromium은 사용자 PC의 Google 로그인과 별개다. 플랫폼 Google credential 파일을 사용자 원본 접근 권한으로 사용하지 않았다. GH/CF 인증은 이미 사용 가능하다. 추가 네트워크 공개나 임의 이메일 공유, 쿠키/비밀번호/토큰 제출을 요구하지 않는다.

이전에 받은 시트 ID, 사진 ID 대응, 서버 원문, 푸시 비밀값, ZIP은 확보돼 있다. 최신 교사 세션 응답과 백업 이후 원본만 부족하다. 아래 **한 묶음**으로 확보한다. Google 연결을 다시 시도할 필요는 없다.

## 사용자가 지금 할 일 — 운영 쓰기는 계속 열어 둔다

### 1. 실제 교사 피드 오류 진단 파일

[진단 코드 열기](https://github.com/rlasksk030/okgu-diary-alarm-/blob/codex/2026-10-02-okgu-speed/scripts/teacher-feed-diagnostic.js) → **Raw**를 눌러 코드 전체를 복사한다. 이 파일에는 비밀값이 없다.

1. Chrome에서 **기존 학생용 주소**를 열고 선생님 계정으로 로그인한다. 작성 중 내용이 있으면 먼저 따로 보관한다. 앱 저장소 삭제/로그아웃/강제 새로고침은 필요 없다.
2. Chrome **⋮ → 도구 더보기 → 개발자 도구 → 소스(Sources)**. 폭이 좁으면 **»**에서 **스니펫(Snippets)**을 찾는다.
3. **새 스니펫(New snippet)** → `okgu-feed-check`라는 이름 → 복사한 코드를 붙여 넣는다.
4. macOS **⌘+Enter**, Windows **Ctrl+Enter**로 한 번 실행한다.
5. 내려받은 **okgu-teacher-feed-diagnostic.private.json**을 이 대화에 첨부한다.

기존 브라우저의 인증을 메모리에서만 사용해 정상 교사 조회를 수행한다. 다운로드에는 성공 여부/오류 분류/시간/응답 모양/행 개수/날짜 형식만 담는다. 이름·본문·일기 ID·사진 URL·PIN·토큰·GAS URL은 담지 않는다. 작성/삭제/알림 발송/진단 서버 전송은 하지 않는다. 기존 GAS 조회 함수의 내부 동작은 현재 코드 확인 전 별도로 단정하지 않는다. 브라우저의 붙여넣기 경고를 해제하라고 안내하지 않는다.

### 2. 최신 비공개 원본 백업 — 기존 운영 프로젝트에서 ID 재입력 없이

[ReadOnlyOperationalExport.gs 열기·다운로드](https://github.com/rlasksk030/okgu-diary-alarm-/blob/codex/2026-10-02-okgu-speed/migration/source/ReadOnlyOperationalExport.gs). GitHub 파일의 **Download raw file** 아이콘으로 내려받거나 **Raw**의 전체 텍스트를 복사한다. 실제 다운로드 첨부라고 주장하는 `/workspace` 링크가 아니다. 공개 가능한 일반 helper이며 학생 자료/시트 ID/비밀값이 없다.

1. 운영 원본 Google 시트 → **확장 프로그램 → Apps Script**. 기존 웹 앱이 별도 프로젝트라면 [Apps Script](https://script.google.com/home)에서 **실제로 현재 운영 중인 서버 프로젝트**를 연다. 새 빈 프로젝트에 이 helper만 붙이면 기존 상수가 없어 실행되지 않는다.
2. **편집기 → 파일 옆 + → 스크립트** → 이름 `ReadOnlyOperationalExport`.
3. **새로 만든 파일만** 기본 내용을 지우고 helper 전체를 붙여 넣는다. 원래 `Code.gs`를 지우거나 바꾸지 않는다. 같은 helper를 이미 추가했다면 중복 파일을 만들지 않는다.
4. **프로젝트 저장**(디스크 아이콘/⌘S/CtrlS).
5. 상단 함수 선택에서 **backupOkguWithKnownSource → 실행**.
6. 권한 창의 **권한 검토 → 운영 자료 소유자 Google 계정 → 요청 권한 확인 → 허용**. 본인이 추가한 이 프로젝트인지 확인한다. 관리자가 차단하면 중단하고 차단 사유만 알려준다. 비밀번호/권한 토큰을 채팅에 보내지 않는다.
7. **실행 로그**의 `complete:true`, `copied:total`, `verified:total`을 확인한다. `complete:false` 또는 실행 시간 초과라면 **같은 backupOkguWithKnownSource를 다시 실행**한다. 기존 checkpoint에서 이어 가며 사진을 처음부터 중복 복사하지 않는다.
8. Google Drive에서 **옥구_최종백업_날짜_시간** 폴더 검색 → `backup-status.txt` 첫 줄 **COMPLETE**, `raw.private.json`, `operating-runtime.private.json`, 사진 `.original` 파일을 확인한다. `.original` 물리 파일 수만으로 완료를 판단하지 않는다. 같은 bytes는 하나의 파일을 공유하며 원본별 ID/참조 대응과 전체 checksum 검증 결과가 raw에 담긴다.
9. Drive 폴더 우클릭 → **다운로드** → ZIP 다운로드가 끝나면 **ZIP 전체를 이 대화에 비공개 첨부**한다. 파일 이름만 변경해도 되지만 raw/사진/상태 파일을 빼지 않는다. GitHub/공개 링크로 올리지 않는다.

원본 시트와 사진은 읽기만 한다. 쓰는 곳은 **새 소유자 전용 비공개 Drive 백업 폴더와 `OKGU_` 백업 checkpoint 속성**뿐이다. 기존 세션 속성·쓰기 상태·운영 트리거·원본 사진·원래 Code.gs를 변경하거나 푸시를 보내지 않는다. Google OAuth의 Drive 권한 자체는 쓰기 가능하므로 “읽기 전용 OAuth”라고 설명하지 않는다. 익명 Web App 호출은 백업을 시작/재개/초기화할 수 없다. source 폴더 이름이 중복이면 추측하지 않고 중단한다. 실제 Google 실행은 아직 작업자가 검증하지 못했다.

**이 백업 때문에 배포/새 배포/쓰기 중단을 누르지 않는다.** 백업 중 원본 변화가 감지돼 `SOURCE_CHANGED_START_NEW_BACKUP`, `PHOTO_CHANGED_START_NEW_BACKUP`, `PHOTO_INVENTORY_CHANGED_START_NEW_BACKUP`이면 **startNewOkguBackup → 실행**으로 새 폴더를 시작하고, 다시 **backupOkguWithKnownSource**를 완료될 때까지 실행한다. 이전 폴더는 보존한다. 기존 checkpoint가 이미 완료된 상태에서 나중 시점 백업을 만들 때도 startNew로 시작한다. 불완전 ZIP을 최종 자료로 인정하지 않는다.

이미 ZIP을 만들어 준 Google 연결 도구에서 동일한 원본 전체를 새로 읽어 complete/checksum/원본ID 대응을 보존한 ZIP을 만들 수 있다면 그 경로를 대신 써도 된다. **두 경로를 모두 수행할 필요는 없다.** 옛 사본을 재압축하면 최신 일기가 포함되지 않는다. 동결 이후 연속 캡처도 가능한 경로여야 한다.

### 3. 자동으로 읽을 수 없는 운영 배포/예약만 확인

같은 프로젝트 **배포 → 배포 관리 → 사용 중인 웹 앱**의 버전 번호 및 코드가 처음 첨부한 서버 코드와 동일한지만 알려준다(“동일, 버전 N”). 다르면 **해당 배포 버전 코드만** 비공개 파일로 첨부한다. editor 최신 코드와 실제 활성 버전은 다를 수 있다. helper가 수집한 metadata는 editor 상태이며 활성 버전 동일성을 증명하지 않는다.

**트리거**에서 `scheduledDiaryReminderPush`의 실제 예약 시간과 개수, **실행**에서 그 함수의 가장 최근 실행 시각/완료·실패 상태를 알려준다. helper가 프로젝트 시간대/핸들러 목록은 수집하므로 같은 정보를 따로 적지 않아도 된다. Trigger API로 예약 시각과 진행 중 실행을 읽을 수 없어서 이 부분만 화면 확인이 필요하다. 아직 트리거를 삭제하거나 알림 함수를 수동 실행하지 않는다.

필수 전달 묶음: **진단 JSON + 최신 COMPLETE ZIP + 활성 배포 동일 여부/버전 + 밤22시 예약·최근 실행 상태**. 이미 제공된 ID·PIN·비밀값은 다시 요구하지 않는다.

## 최종 변화분 확보와 쓰기 중단 순서 — 현재는 실행하지 않음

1. **수집 경로부터 검증**: 위 최신 완전 백업을 열어 전체 10시트/원본 사진/원본ID 대응/실제 교사 오류/활성 서버 버전을 확인한다. 제공 코드와 같으면 기존 명시적 열 대응표를 적용하고, 다르면 그 버전 기준으로 위치를 다시 검토한다. `identityReviewed:false`를 추측으로 해제하지 않는다. 추가·수정·삭제 목록을 이전 19:53 캡처와 대조한다.
2. **동결 전 준비**: 최신 매핑·암호화 원본 백업·운영 전용 D1/R2·미연결 paused 후보를 준비하고 private 파일 업로드/대조 시간을 확인한다. 가상 trial을 운영으로 승격하지 않는다. 최종 스냅샷으로 미연결 운영 target을 구성하는 경로를 사용하며 기존/new target 행을 자동 덮어쓰지 않는다. 원격 실제 반입·대규모 실행 journal은 최신 매핑 뒤 실행 검증해야 하며 이미 완료했다고 표현하지 않는다.
3. **작성 내용 보호**: 저장 중/사진 업로드 중인 탭은 닫거나 새로고침하지 않는다. 본문 별도 복사, 원본 사진 기기 보관을 안내한다. 새 앱은 실패 시 본문/첨부/공개 범위를 유지한다. 원래 앱의 브라우저 종료 후 초안 영구 보존은 보장하지 않는다.
4. **짧은 동결 시작**: 현재 운영 코드와 일치하는 검토된 freeze patch를 배포하고 **프로젝트 설정 → 스크립트 속성 → OKGU_WRITE_PAUSED = yes**를 활성화한다. 기존 URL의 일반 저장·사진·직접 호출을 가상/확인 계정으로 거절하는지 검증한다. 속성만 설정하고 guard 미설치 상태를 동결됐다고 판단하지 않는다. 현재 helper는 getSheet를 쓰지 않아 계속 읽을 수 있다. 일부 옛 조회도 guard로 잠시 막힐 수 있다.
5. **진행 중 요청 종료**: Apps Script **실행**에서 기존 저장·수정·삭제·사진·알림 실행이 모두 종료됐는지 확인하고 그 뒤 시각/배포 버전을 비공개 journal에 남긴다. 이미 들어간 작업은 속성 변경만으로 취소되지 않는다. 처리 중 요청/발송 상태가 불명확하면 최종 캡처 기준을 확정하지 않는다.
6. **동결 후 A/B 연속 완전 캡처**: A는 startNew → backupOkguWithKnownSource 반복 → COMPLETE → 다운로드, A 완료 후 B도 같은 순서로 새로 시작한다. 두 ZIP과 실시간 확인 journal로 아래 gate를 실행한다. V1 옛 ZIP/동결 전 최신 ZIP만으로 안정된 마지막 자료를 증명하지 않는다. B의 모든 셀/사진/참조가 A와 동일하고 각각 실제 bytes/checksum이 맞아야 한다. 새 기록뿐 아니라 수정·삭제도 전체 원본 비교에 포함한다. 원본에서 삭제된 행은 검토 후 최종 활성 목록에서 제외하되 이전 백업/archive에서 보존한다.
7. **최종 대조와 연결**: B의 원본 값·작성자·날짜·공개 범위·PIN hash·댓글/게시판/좋아요 관계·사진 원본 bytes를 운영 D1/R2와 전부 대조한다. 기존 source 고아 관계도 archive 보존 여부를 검사한다. 일치 전에는 main/기존 Pages를 변경하지 않는다. 기존 승인 범위에서 검증된 후보를 main 루트에 반영하고 원래 GitHub Pages 주소/manifest/scope/SW를 유지한다. 별도 검증 계정으로 Pages→Worker 로그인·조회·글/사진·교사 PIN·ACL/GAS 요청0을 확인한다. 검증을 위해 쓰기를 열었다면 생성된 신규 target 자료도 이후 모든 백업에 포함한다.
8. **쓰기 재개**: 새 Worker active/자산과 CORS/auth 전파 확인 후 **D1 공통 쓰기 장벽을 마지막으로 해제**한다. 옛 GAS는 paused로 유지한다. 신규 자료가 생긴 target에 최종 원본 import를 재실행해 덮어쓰지 않는다. 중단 소요는 실제 Google 수집/자료 반입이 확인되기 전 추정하지 않는다.

최종 시각은 **안정 검사를 통과한 B의 capturedAt**으로 기록한다. 현재 그 시각은 미확정이며 확보된 19:53:01 KST를 최종 이전 기준이라고 사용하지 않는다.

```sh
# 모두 .local 하위 비공개 경로. 실제 학생 자료를 공개 출력하지 않는다.
node scripts/check-final-source.mjs .local/final-A/raw.private.json .local/final-B/raw.private.json .local/final-freeze.private.json
```

journal에는 실제 확인한 `ownerConfirmedPausedDeployment:true`, `freezeGuardVerified:true`, `pendingWrites:0`, `pendingOldPushExecutions:0`, `deploymentVersion`, `pausedAt`(ISO 시간대 포함)를 기록한다. 빈 journal/추측 값은 통과시키지 않는다. 도구는 원본·트리거를 변경하지 않고 두 캡처 안정/전체 사진 bytes를 검사한다. `eligibleForPrivateDataComparison:true`는 **운영 전환 성공이 아니다.** D1/R2 전체 값/ACL/Pages 비교는 다음 별도 단계다.

## 밤22시 알림과 실패 시 복구

전환 전 담당은 기존 GAS `scheduledDiaryReminderPush` → Vercel이며 설정을 유지한다. 제공 코드는 atHour(22)/nearMinute(0)/everyDays(1)를 사용하고 명시적 inTimezone이 없어 **운영 프로젝트 시간대와 실제 트리거를 확인해야 한다**. 기존 GAS에는 일자별 발송 완료 ledger가 없다. 프로젝트 설정을 읽지 않고 “오늘22시 발송 완료”라고 추정하지 않는다. 현재 새 Worker PUSH disabled/cron0, 실제 학생 시험 발송0.

전환 때 기존 트리거 설정 보관 → 기존 예약 OFF + 진행 중 발송 종료 + source guard → 같은 KST 일자 실행 결과 확인 → D1 미작성/교사제외/day+student dedupe → 새 `0 13 * * *` 및 분 단위 dispatcher ON 순서다. **이미 옛22시 실행이 끝났거나 완료 여부가 모호한 날에는 그날 새 전체 미작성 알림을 억제**하고 다음 KST 날짜부터 새 예약을 사용한다. 학생별 수신 성공을 모르는 상태에서 성공 ledger를 만들어 추정하지 않는다. 두 서버가 동시에 발송하지 않도록 한다. 원본 코드/설정 백업은 보존한다.

실패 시 D1 장벽 잠금 → Worker paused/PUSH disabled/cron OFF → 진행 중 작업 종료 → **전환 후 신규 글·수정·삭제·현재 PIN·댓글/사진까지 최신 D1/R2 암호화 백업** → 호환 코드/격리 복원 → 전체 값/bytes/ACL 대조 → Pages 재연결 → 장벽 마지막 해제. 옛 ZIP으로 덮어쓰거나 단순 GAS URL 복귀하지 않는다. 완전 GAS 역방향 복귀 미지원 한계는 사용자가 이미 수용했다.
