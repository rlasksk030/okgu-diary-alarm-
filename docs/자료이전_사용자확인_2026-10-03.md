# 자료 이전 전 사용자 확인 — 부족한 항목만

25d326e에서 이어서 준비했습니다. 새 기능·속도 최적화·실제 자료 반입·운영 전환은 하지 않았습니다. 로그인 API p95 **3.64초**는 1초 목표 미달로 유지합니다. 이 결과만으로 다른 준비를 중단하지 않으며, **최종 운영 전환 승인 때 이 속도를 수용할지 확인**합니다.

## 한 번에 준비할 부족한 자료

### 1. 원본 시트·사진의 비공개 export와 사진 폴더 링크

1. 운영 일기 시트를 사용하는 Google 계정으로 Drive를 엽니다. 위 시트 ID는 이미 확보했으므로 다시 전달할 필요가 없습니다.
2. Drive 상단 검색창에 **`OKGU_DIARY_사진`**을 입력합니다. 폴더를 선택해 **공유 → 링크 복사**로 폴더 링크만 알려주세요. 같은 이름의 폴더가 여러 개면 각각의 링크와 개수를 알려주세요. **일반 액세스는 제한됨**으로 유지합니다.
3. Drive에서 **새로 만들기 → 새 폴더**로 `옥구_이전백업_날짜`를 만듭니다. **공유 → 일반 액세스: 제한됨**, 다른 뷰어·편집자 없이 소유자만 있는 폴더여야 합니다. 주소의 `/folders/` 뒤 문자열이 백업 폴더 ID입니다.
4. [별도 Apps Script 프로젝트](https://script.google.com/home/start)를 새로 엽니다. **운영 프로젝트를 수정하지 않습니다.** [ReadOnlyExport.gs](../migration/source/ReadOnlyExport.gs)의 전체 코드를 새 `Code.gs`에 넣습니다.
5. 왼쪽 **프로젝트 설정 → 스크립트 속성 → 스크립트 속성 추가**에서 다음 두 개를 저장합니다. `OKGU_SOURCE_SPREADSHEET_ID`: 처음 첨부한 운영 Code.gs 첫 줄에 있는 값. `OKGU_PRIVATE_BACKUP_FOLDER_ID`: 3번의 새 백업 폴더 ID. 비밀번호·API 키 입력은 필요 없습니다.
6. **편집기**로 돌아가 위쪽 함수 선택에서 **`exportOkguReadOnly` → 실행**. 소유자의 Sheets/Drive 읽기 및 별도 백업 폴더 쓰기 권한을 승인합니다. 이 함수는 운영 시트·사진·트리거·공유 권한을 수정하지 않습니다.
7. 새 백업 폴더 안에 `okgu-source-….private.json`과 `.original` 파일들이 생겼는지 확인합니다. **완료된 JSON의 `complete:true`가 없는 부분 백업은 보내지 않습니다.** 실행 제한 오류가 나면 오류 코드/완료 여부만 알려주세요. 로그나 PIN 셀을 복사하지 않습니다.
8. 백업 폴더를 **다운로드**해 비공개 ZIP으로 보관하고, 학생 자료 제공에 사용하는 **이 대화의 파일 첨부**로 전달합니다. 본문에 PIN·본문·키를 붙이지 않습니다. GitHub/공개 Drive 링크/시험 앱에 올리지 않습니다. 반입 후 작업자는 Git 제외 `.local/private-source/`에만 풀고 권한을 제한하며 공개 시험 DB에는 넣지 않습니다.

원본 폴더 링크는 아직 모르는 정확한 ID를 확인하기 위한 것입니다. 실제 연결 사진은 시트의 각 파일 ID로 원본을 읽습니다. 미연결 사진은 임의로 버리거나 학생에게 연결하지 않고 별도 보존 목록으로 검토합니다. exporter는 가상 구조 검증만 끝났으며 실제 Google 실행은 아직 하지 않았습니다.

### 2. 현재 Apps Script 배포와 트리거의 확인

1. 운영 시트의 **확장 프로그램 → Apps Script**를 엽니다. 별도 프로젝트라면 기존 서버 프로젝트를 엽니다.
2. 우측 **배포 → 배포 관리**에서 사용 중인 웹 앱을 선택합니다. 배포 버전 번호와 현재 첨부 코드가 같은지 알려주세요. **편집·새 배포·삭제는 누르지 않습니다.** 프로젝트 편집기의 미배포 최신 코드와 현재 학생 웹 앱 버전을 구분합니다.
3. 코드가 처음 첨부본과 같다면 **“첨부 코드와 현재 배포 코드 동일, 버전 N”**이라고만 알려주세요. 다를 때만 해당 버전의 코드 파일을 추가로 제공합니다. 비밀 상수의 값은 `[REDACTED]`로 바꾸고 파일 첨부로 전달합니다. 이미 받은 비밀값을 다시 요구하지 않습니다.
4. 왼쪽 시계 아이콘 **트리거**에서 `scheduledDiaryReminderPush` 행의 존재/개수/시간을 확인합니다. 개인정보를 가린 화면 또는 함수 이름·시간만 전달해주세요. **삭제·추가·실행하지 않습니다.** 특히 `testNightlyDiaryReminderPushNow`는 실제 미작성 학생에게 보내므로 실행하지 마세요.
5. **프로젝트 설정**에서 표시한 `appsscript.json`의 `timeZone`만 확인합니다. 현재 값이 `Asia/Seoul`인지 알려주세요. 다른 설정·비밀값은 보내지 않습니다.

### 3. 기존 Vercel 푸시 서버의 소스 위치

Vercel에서 **프로젝트 `okgu-push-server030` → Settings → Git → Connected Git Repository**의 저장소 링크만 알려주세요. Git 연결이 없다면 배포 서버 소스를 비밀값 제거 파일로 제공합니다. **Settings → Environment Variables**에서는 키 이름/설정 여부만 확인하고 값을 Reveal·복사하지 않습니다. 현재 실제 배포의 VAPID 공개키가 운영 main과 같은지 확인할 수 있으면 동일 여부만 알려주세요. 현재 Bearer 연결 설정은 이미 있으므로 다시 보내지 않습니다.

## 실물 휴대전화에서 짧게 확인하기

운영 앱은 그대로 두고 [분리 시험 앱](https://okgu-diary-pages-trial.rlasksk030.workers.dev/okgu-diary-alarm-/)에서 합니다. 실제 학생 이름·자료를 쓰지 마세요.

1. **시험학생13 / PIN `0042`**, **30일간 로그인 유지**를 선택해 로그인합니다. 앞자리 0도 입력합니다.
2. 짧은 가상 일기와 시험 사진을 첨부해 **나만 보기 → 오늘 기록 저장**. 저장 완료 뒤 기록과 사진을 다시 엽니다.
3. Android Chrome의 **홈 화면에 추가/앱 설치**, iPhone Safari의 **공유 → 홈 화면에 추가**로 **시험 앱**을 설치합니다. 앱을 닫았다 다시 열고 새로고침해 로그인·사진 유지 여부를 확인합니다. 삭제/재설치하지 말고 결과와 OS·브라우저만 알려주세요.
4. **로그아웃 → 시험학생12 / 0042**로 바꾸고 앞 사용자의 기록·사진·초안이 남지 않는지 확인합니다.
5. PIN 재설정 실기까지 확인할 때는 PC 등 다른 브라우저에서 **가상교사 / 0042 → 교사 대시보드 → 학생 → 시험학생13 → PIN 재설정**. 새 PIN과 확인을 **`0024`**로 저장합니다. 휴대전화의 기존 시험학생13 세션이 만료되고 `0042`는 실패, `0024`는 로그인되며 이전 기록·사진이 남는지 확인합니다. 끝나면 교사 화면에서 **`0042`로 다시 재설정**하고 다음 시험부터 재로그인합니다.

이는 실물 **시험 PWA** 확인입니다. 이미 설치된 **운영 주소 PWA의 실제 전환 후 업데이트**까지 확인한 것으로 보고하지 않습니다. 그 확인은 최종 승인 뒤 기존 주소를 유지한 전환 점검에 포함합니다. 30일 동안의 경과 시험도 아직 한 것은 아닙니다.

## 실제 푸시가 필요한 경우의 사전 특정

현재 시험은 푸시 **차단·cron 0**, 실제 학생 발송 0입니다. 실제 전달 확인이 필요한 단계에서는 먼저 **사용자 본인 휴대전화의 가상 시험 계정 1개**와 구독 endpoint를 비공개로 특정합니다. 제목 **“옥구 다이어리 시험 알림”**, 본문 **“가상 계정 알림 연결 확인입니다.”**, 시험 앱 주소, 수동 1회만 제시하고 별도 발송 승인을 받습니다. 학생 명단/기존 학생 구독/미작성 전체 알림은 대상에 넣지 않습니다. 이 문서는 발송 승인이나 운영 알림 전환이 아닙니다.

## 운영 전환 판단

현재는 **이전 준비를 보존한 상태이며 운영 전환은 아직 불가**입니다. 실제 자료 대조·현 배포/트리거·실물 PWA·푸시 서버 호환·운영 전용 리소스/Pages 설정 확인이 남습니다. 실제 규모가 나오면 변화분 묶음과 백업 저장·복구 키 보관 방법을 확정합니다. 최종 승인 때 로그인 p95 3.64초 수용 여부와 **완전 GAS 복귀 대신 최신 D1/R2 유지 또는 별도 복원 방식의 복구 한계**를 함께 확인합니다. 속도 수용만으로 자료 검증을 생략하지 않습니다.
