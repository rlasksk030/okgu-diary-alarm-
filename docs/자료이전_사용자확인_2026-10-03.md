## 한 번에 준비할 부족한 자료

### 1. 원본 시트·사진의 비공개 export와 사진 폴더 링크

**현재 크롬에서 가장 짧게 진행하는 방법:** 사용자 PC 크롬을 직접 조작하는 연결은 현재 없으며, 클라우드 Chromium의 로그인도 사용자 Google 로그인과 별개입니다. 크롬에서 운영 자료의 소유자 계정으로 아래를 진행합니다.

1. 작업공간의 **`.local/private-source-export/ReadOnlyExport.private.gs`**를 엽니다. 처음 받은 시트 ID가 이미 반영되어 있고, 원본 서버의 푸시 비밀값/학생 자료는 들어 있지 않습니다. 이 파일은 Git 제외・권한600이며 공개 GitHub에는 없습니다.
2. [새 Apps Script 프로젝트](https://script.google.com/home/start)를 열어 **`Code.gs` 전체를 위 파일 내용으로 교체 → 저장**합니다. 기존 운영 프로젝트를 열어 수정하는 방식이 아닙니다. **배포하지 않습니다.**
3. 위쪽 함수 목록에서 **`backupOkguWithKnownSource` → 실행**을 선택하고 Google 접근 권한을 확인합니다. 새 소유자 전용 `옥구_이전백업_YYYYMMDD_HHMMSS` 폴더를 만들고 원본을 읽어 백업합니다. 스크립트 속성이나 시트 ID를 별도로 입력할 필요가 없습니다.
4. Drive에서 새 백업 폴더를 찾아 **우클릭 → 다운로드**하여 ZIP을 비공개로 보관하고 이 대화에 **파일 첨부**합니다. 완료 JSON/사진이 생기기 전에 실행이 오류로 끝나면 완료 백업으로 사용하지 말고 오류 코드만 알려주세요. 원본 사진 폴더의 정확한 링크와 현재 배포 확인은 아래 항목대로 함께 제공합니다.

이 helper는 **Google에서 아직 실행하지 않았습니다.** 파일을 새 환경에서 다시 만들 때는 `node scripts/prepare-private-source-export.mjs <이미 확보한 비공개 서버 원문 파일>`을 사용합니다. 원문과 생성 파일은 Git에 올리지 않습니다. 일반 코드로 직접 설정하려면 아래 절차를 사용하며 **두 방법을 모두 실행할 필요는 없습니다.**

1. 운영 일기 시트를 사용하는 Google 계정으로 Drive를 엽니다. 위 시트 ID는 이미 확보했으므로 다시 전달할 필요가 없습니다.
2. Drive 상단 검색창에 **`OKGU_DIARY_사진`**을 입력합니다. 폴더를 선택해 **공유 → 링크 복사**로 폴더 링크만 알려주세요. 같은 이름의 폴더가 여러 개면 각각의 링크와 개수를 알려주세요. **일반 액세스는 제한됨**으로 유지합니다.
3. Drive에서 **새로 만들기 → 새 폴더**로 `옥구_이전백업_날짜`를 만듭니다. **공유 → 일반 액세스: 제한됨**, 다른 뷰어·편집자 없이 소유자만 있는 폴더여야 합니다. 주소의 `/folders/` 뒤 문자열이 백업 폴더 ID입니다.
4. [별도 Apps Script 프로젝트](https://script.google.com/home/start)를 새로 엽니다. **운영 프로젝트를 수정하지 않습니다.** [ReadOnlyExport.gs](../migration/source/ReadOnlyExport.gs)의 전체 코드를 새 `Code.gs`에 넣습니다.
5. 왼쪽 **프로젝트 설정 → 스크립트 속성 → 스크립트 속성 추가**에서 다음 두 개를 저장합니다. `OKGU_SOURCE_SPREADSHEET_ID`: 처음 첨부한 운영 Code.gs 첫 줄에 있는 값. `OKGU_PRIVATE_BACKUP_FOLDER_ID`: 3번의 새 백업 폴더 ID. 비밀번호·API 키 입력은 필요 없습니다.
6. **편집기**로 돌아가 위쪽 함수 선택에서 **`exportOkguReadOnly` → 실행**. 소유자의 Sheets/Drive 읽기 및 별도 백업 폴더 쓰기 권한을 승인합니다. 이 함수는 운영 시트·사진·트리거·공유 권한을 수정하지 않습니다.
7. 새 백업 폴더 안에 `okgu-source-….private.json`과 `.original` 파일들이 생겼는지 확인합니다. **완료된 JSON의 `complete:true`가 없는 부분 백업은 보내지 않습니다.** 실행 제한 오류가 나면 오류 코드/완료 여부만 알려주세요. 로그나 PIN 셀을 복사하지 않습니다.
8. 백업 폴더를 **다운로드**해 비공개 ZIP으로 보관하고, 학생 자료 제공에 사용하는 **이 대화의 파일 첨부**로 전달합니다. 본문에 PIN·본문·키를 붙이지 않습니다. GitHub/공개 Drive 링크/시험 앱에 올리지 않습니다. 반입 후 작업자는 Git 제외 `.local/private-source/`에만 풀고 권한을 제한하며 공개 시험 DB에는 넣지 않습니다.

원본 폴더 링크는 아직 모르는 정확한 ID를 확인하기 위한 것입니다. 실제 연결 사진은 시트의 각 파일 ID로 원본을 읽습니다. exporter가 만드는 백업에는 **시트에 연결된 사진만** 포함됩니다. 원본 사진 폴더 전체도 우클릭 **다운로드**로 별도 비공개 ZIP을 보관하면 미연결 사진까지 보존할 수 있습니다. 원본 시트는 **파일 → 다운로드 → Microsoft Excel(.xlsx)**로 별도 보관합니다. 이전에는 exporter JSON의 실제 열·타입·표시 형식과 원본 사진을 사용하고 XLSX만으로 PIN 형식·관계를 추측하지 않습니다. 미연결 사진은 임의로 버리거나 학생에게 연결하지 않습니다. exporter는 가상 구조 검증만 끝났으며 실제 Google 실행은 아직 하지 않았습니다.

### 3. 기존 Vercel 푸시의 현재 배포 설정만 확인

서버 저장소는 직접 찾았으므로 링크나 서버 코드를 다시 제공할 필요가 없습니다. 읽기 전용으로 확인한 소스는 [rlasksk030/okgu-push-server](https://github.com/rlasksk030/okgu-push-server), `main` 커밋 **`92673c980767b4eeb3b0ff6f9fda05d6cc4baaf1`**입니다. Bearer 인증, 요청 subscriptions/title/body/tag/url, 기본 아이콘, expired endpoint 응답이 Workers와 호환됩니다. 실제 Vercel에 수신자 `[]`만 보내 HTTP200, sent0/failed0/expired0을 확인했습니다. 학생 발송과 실제 기기 전달 검증은 아닙니다.

1. Vercel **프로젝트 `okgu-push-server030` → Deployments → 현재 Production 배포 → Source/Commit**에서 현재 커밋이 위 소스와 같은지 확인하고 커밋 번호만 알려주세요. GitHub 쪽 배포 기록은 없어서 실제 Vercel 커밋은 자동 확인하지 못했습니다.
2. **Settings → Environment Variables**에서 `VAPID_PUBLIC_KEY`만 운영 HTML의 `PUSH_PUBLIC_KEY`와 같은지 확인하고 **“공개키 동일/다름”만** 알려주세요. 이는 공개키 비교이며 값을 대화에 보낼 필요가 없습니다. `VAPID_PRIVATE_KEY`와 `PUSH_SECRET`은 Reveal·복사하지 않습니다. 현재 Bearer 설정은 이미 확보하고 실제 인증도 통과했습니다.

2. 짧은 가상 일기와 시험 사진을 첨부해 **나만 보기 → 오늘 기록 저장**. 저장 완료 뒤 기록과 사진을 다시 엽니다.

4. **로그아웃 → 시험학생12 / 0042**로 바꾸고 앞 사용자의 기록·사진·초안이 남지 않는지 확인합니다.

## 실제 푸시가 필요한 경우의 사전 특정

현재 시험은 푸시 **차단·cron 0**, 실제 학생 발송 0입니다. 실제 전달 확인이 필요한 단계에서는 먼저 **사용자 본인 휴대전화의 가상 시험 계정 1개**와 구독 endpoint를 비공개로 특정합니다. 제목 **“옥구 다이어리 시험 알림”**, 본문 **“가상 계정 알림 연결 확인입니다.”**, 시험 앱 주소, 수동 1회만 제시하고 별도 발송 승인을 받습니다. 학생 명단/기존 학생 구독/미작성 전체 알림은 대상에 넣지 않습니다. 이 문서는 발송 승인이나 운영 알림 전환이 아닙니다.

## 운영 전환 판단

**승인은 확보했지만 원본이 없어 운영 전환을 실행하지 못했습니다.** 시트·원본 사진을 받은 뒤 실제 자료 대조와 현재 GAS 배포/트리거를 확인하고 승인된 순서대로 진행합니다. GitHub main/Pages 변경 권한과 Cloudflare 인증은 정상이며 사용자에게 Cloudflare 로그인이나 토큰을 다시 요구하지 않습니다. Pages는 실제로 `legacy`, `main`, `/` 배포임을 확인했습니다. 운영 API/Pages 후보를 오프라인 생성·검사했고 아직 운영 리소스 생성·배포·쓰기 중단은 하지 않았습니다. 실제 규모가 나오면 변화분 묶음과 비공개 백업·복구 키 보관 방법을 확정합니다. 속도·복구 한계 수용과 운영 전환 승인은 유효하며 재승인하지 않습니다.
