# 운영 전환 실행안 — 승인 전 준비

현재 상태는 시험 검증과 전환 준비입니다. 운영 전환은 실행하지 않았습니다. 실제 자료 대조・현재 배포/트리거・실물 PWA/푸시・운영 리소스/Pages 설정이 남아 **현재 운영 전환 보류**입니다. 로그인 p95 3.64초는 1초 목표 미달로 기록하고 최종 전환 승인 때 수용 여부를 확인합니다. 이것만으로 나머지 이전 준비를 중단하지 않습니다. 아래 절차는 승인 뒤의 작업 순서이며 지금 실행하는 명령이 아닙니다. 운영 main은 `964985d3ff683617de18e89f71521f2c224d50f2`입니다. 부족한 자료만 모은 [사용자 확인 안내](자료이전_사용자확인_2026-10-03.md)를 먼저 봅니다.

## 원본 확보와 비공개 백업

첨부한 서버 **원문**과 운영 시트 ID・사진 폴더 이름・기존 푸시 연결 설정은 이미 확보했습니다. Git에는 `reference/Code.original.redacted.gs`만 보관합니다. 현재 배포와의 일치, 실제 셀/Drive bytes, Google 읽기 권한은 확인하지 못했습니다. 이미 받은 코드・ID・비밀값을 다시 요구하지 않습니다. 코드가 다를 때만 비밀값 제거 최신 파일을 받고, 원본은 소유자의 비공개 export로 조사합니다. 익명 구형 API로 학생 명단이나 기록을 수집하지 않았습니다. 비밀값/학생 파일은 Git・공개 시험・채팅 본문으로 전달하지 않습니다.

소유자가 직접 내보낼 때:

1. Google Drive에서 **새로 만들기 → 새 폴더**, 공유 → **일반 액세스: 제한됨**, 공동 편집자/뷰어 없는 별도 백업 폴더를 만듭니다.
2. 별도 Apps Script 프로젝트에 `migration/source/ReadOnlyExport.gs`를 복사합니다. 운영 프로젝트나 트리거를 바꾸지 않습니다.
3. **프로젝트 설정 → 스크립트 속성 → 스크립트 속성 추가**에 `OKGU_SOURCE_SPREADSHEET_ID`(원본 ID), `OKGU_PRIVATE_BACKUP_FOLDER_ID`(위 백업 폴더 ID)를 설정합니다. 값을 Git이나 대화에 넣지 않습니다.
4. **편집기 → exportOkguReadOnly → 실행**. Sheets/Drive 접근을 확인합니다. 코드는 원본을 읽고 별도 비공개 폴더에만 백업을 만듭니다. Apps Script가 시간/용량 제한으로 끝나면 부분 백업을 완전 백업으로 쓰지 않습니다. 대규모 자료는 승인된 읽기 전용 다운로드 도구가 별도로 필요합니다. 원본 파일을 지우거나 공유 권한을 바꾸지 않습니다.
5. 비공개 JSON과 `.original` 사진 파일을 안전한 전달 경로로 확보합니다. 원본 XLSX/시트 복사도 별도 비공개 백업으로 보관합니다. Code의 `getSheet()`는 시트/헤더를 만들 수 있어 exporter에서 사용하지 않습니다.

Exporter는 실제 열 순서·원시 값·표시 값·날짜 형식·수식·시간대를 보존합니다. 날짜 셀은 typed ISO 값입니다. Drive `thumbnail?...w600` URL은 원본이 아니므로 파일 ID로 `getBlob()`한 원본을 백업합니다. 이 Apps Script exporter는 구문만 검사했고 Google 계정에서 실행하지 않았습니다.

## 원본 검토와 가상 예행연습

원본은 `.local/private-source/` 등 Git 제외 디렉터리에 권한600으로 보관합니다. `identity.private.json`은 `reviewed:true`, `capturedSourceHash`(raw 파일의 SHA256), `sourceId`, `classId`, `classLabel`, `timeZone`, `columns`, `columnKinds`, `rowIdentities`를 명시합니다. 각 헤더의 실제 이름과 중복/누락을 확인해야 하며 추가 열·숫자 PIN·모호한 계정은 중단합니다. 원본 계정에 ID 열이 없으므로 외부 고정 identity 대응표를 먼저 확정하고, 행 삽입·이름 변경 후에도 같은 계정 GUID를 재사용합니다. 행 번호를 영구 ID로 추측하지 않습니다. 모든 이름/PIN(0042 등)은 문자열로 보존합니다. 기존 SHA256 해시는 그대로 반입한 뒤 첫 성공 로그인에서 같은 PIN을 PBKDF2-HMAC-SHA256600000으로 업그레이드합니다. PIN 일괄 초기화는 하지 않습니다.

```sh
node --import tsx scripts/normalize-source.mjs .local/private-source/raw.private.json .local/private-source/identity.private.json
npm run migrate:source:rehearsal
npm run migrate:delta:rehearsal
```

정규화는 로컬 파일만 읽고 비공개 snapshot을 만듭니다. `columnKinds`는 실제 Date 셀에 `day` 또는 `timestamp`를 명시하고, 원본 시간대에 맞춰 일기 날짜를 보존합니다. 사진 원본 크기·SHA256가 다르면 중단합니다. 실제 SHA256/PIN/학생 본문을 stdout에 출력하지 않습니다. 검토된 snapshot의 계정·역할·본문/줄바꿈·날짜·공개 범위·작성자·댓글 부모·좋아요·사진 순서/bytes를 엔터티별로 대조합니다. 알림/구독은 현재 archive-only이므로 보존을 확인한 뒤 별도 활성 반입을 검토해야 합니다.

가상 검증은 원본 날짜·계정 hash·원본 사진 checksum 보존, numeric PIN 거부, 재반입 중복 없음, 추가·수정·원자적 충돌 롤백, 재실행, 검토된 삭제, 새 서버 기록 보존을 확인했습니다. 삭제는 완전한 두 snapshot과 `review.currentHash`/`missing[{table,keyHash}]`의 명시적 검토가 있어야 적용됩니다. 일기/게시판/댓글/칭찬은 soft-delete, 사진 metadata/bytes는 복구용으로 남깁니다. 이후 추가/수정된 자식 자료가 있으면 삭제를 거절합니다. 계정/교사 메모 삭제는 별도 검토로 차단합니다. 부재가 삭제라는 가정은 하지 않습니다.

무료 invocation의 50 query 한도 때문에 `applyDelta`는 사전조회1+최대49 statements를 허용합니다. 실제 변화분 규모를 확인한 뒤 의존 관계별 묶음, 동결된 target fingerprint, 완료 journal을 검토해야 합니다. 한 묶음이라도 실패하면 전체 운영 연결을 전환하지 않습니다. 현재 원격 실제 자료 반입 및 큰 변화분 자동 분할은 실행·검증하지 않았습니다.

## 승인 후 실행 순서와 중단 기준

1. **최종 백업**: 원본 Sheets/Drive와 전환 직전 D1/R2를 접근 제한·암호화 백업합니다. 원본과 target baseline의 fingerprint, 정확한 앱/Worker 버전, Pages 설정, VAPID 공개키 fingerprint·비밀키 안전 보관 위치, 트리거 목록을 남깁니다. 새 운영 D1/R2는 가상 시험과 별도 리소스여야 합니다. 시험 계정/자료를 운영으로 승격하지 않습니다.
2. **쓰기 중단**: 검토된 최신 GAS에 오프라인 candidate patch를 적용하고 `OKGU_WRITE_PAUSED=yes`를 설정합니다. `node scripts/prepare-source-freeze.mjs .local/private-source/Code.private.gs`는 로컬 candidate만 만들며 배포하지 않습니다. getSheet・푸시 시트 자동 초기화・사진 폴더 생성・푸시 전송/22시 함수까지 차단합니다. 이미 확보한 첨부 원문으로 오프라인 28개 진입점 차단/Google 서비스 호출0을 확인했지만 현재 운영 배포 실행은 미검증입니다. 별도 exporter는 getSheet를 사용하지 않고 원본을 읽습니다. Apps Script **실행** 목록에서 처리 중 요청 종료, 연속된 완전 snapshot/사진/쓰기 상태의 안정을 확인합니다. 새 Worker는 먼저 관리자가 D1 `UPDATE operation_control SET writes_paused=1 WHERE id=1`로 **공통 쓰기 장벽을 잠근 뒤** `WRITE_MODE=paused`를 배포합니다. RPC API에서 이 관리 행을 수정할 수 없습니다. 환경 설정 전파만으로 동결을 판단하지 않습니다. D1 잠금은 원자적 batch와 오래 실행 중이던 PIN 검증의 뒤늦은 session 생성도 거절합니다. 로그아웃 session DELETE/조회는 허용합니다. 잠금 후 미완료 R2 작업 종료・전체 DB/R2 대조를 확인합니다. 이미 진행 중인 R2 쓰기는 자동 취소되지 않으며 성공한 파일은 원본 참조/ready 여부로 대조하고 미사용 파일을 별도 보존합니다.
3. **최종 변화분 이전**: 초기 백업 이후 추가·수정·검토된 삭제와 새 사진을 적용합니다. 사진은 private R2에 먼저 넣고 크기/checksum을 확인한 뒤 D1 참조를 반영합니다. D1 장벽은 관리자 반입도 차단하므로 운영 target은 아직 공개 연결하지 않은 별도 리소스에서 준비합니다. 검토된 반입 동안만 장벽을 0으로 두고 Worker는 paused/학생 연결 차단, 반입 완료 뒤 다시 1로 잠가 대조합니다. 공개된 기존 target을 임의로 잠금 해제해 반입하지 않습니다. target에 새 자료가 있거나 이름/역할/ID/관계가 모호하면 자동 덮어쓰지 않고 중단합니다.
4. **자료 대조**: entity별 건수만 비교하지 않습니다. 내용·작성자·날짜·공개 범위·PIN 형식·관계·원본 사진 checksum, foreign_key_check, 전체 기간 통계/검색/인쇄를 확인합니다. 누락/불일치가 하나라도 있으면 전환하지 않습니다.
5. **기존 Pages 주소 연결 전환**: 최종 승인된 후보를 main에 반영하고 기존 GitHub Pages source/workflow에서 `build-trial.mjs`의 산출물을 publish합니다. `OKGU_TRIAL_API_ORIGIN`에는 승인된 운영 API origin을 넣되, 이름이 시험용인 배포 guard를 운영에 재사용하지 않습니다. 운영 설정은 별도로 검토해야 하며 main 루트 `index.html`만 복사하면 `config.js`가 없으므로 전환하지 않습니다. 학생 주소/manifest/start_url `./`/scope `./`/아이콘/`sw.js` 경로는 유지합니다. 배포 전 실제 workflow/source를 확인합니다.
6. **로그인·조회·저장·사진·권한 확인**: 같은 이름/PIN, 앞자리0, 개인 기록/사진 교사 차단, 30일 유지/로그아웃/교사 재설정 세션 만료, 전체 인쇄, 브라우저의 GAS 요청0을 확인합니다. 쓰기 전 확인은 paused 상태에서 하고, 소유자가 승인한 소규모 테스트용 계정만 쓰기를 허용하여 저장·재시도·동시 수정 검사를 한 뒤 재개합니다. 시험 가상 계정이 운영 계정 테이블에 섞이지 않게 전용 검증 학급을 분리하거나 격리 검증 DB를 사용합니다.
7. **쓰기 재개**: 허용된 운영 계정과 정확한 Pages 산출물/Worker version을 확인한 뒤 Worker active 배포・전파를 확인합니다. 마지막으로 관리자 D1 `UPDATE operation_control SET writes_paused=0 WHERE id=1`. 0과 실제 저장 성공을 확인한 뒤 재개를 안내합니다. 옛 GAS는 계속 paused로 유지합니다. 동결 중 학생은 작성 탭을 유지하며 실패 안내 뒤 재시도합니다. 실제 시험에서 사진 POST503와 사진 선업로드 후 글503의 본문・첨부・공개 범위・세션 보존, 재개 후 한 건 저장・중복 클릭 방지를 확인했습니다. 새로고침/탭 종료 전에 본문을 별도로 복사하고 원본 사진을 기기에 보관하게 합니다. 초안이 브라우저 종료까지 영구 저장된다고 안내하지 않습니다.
8. **알림 전환 확인**: Apps Script **트리거**에서 기존22시 예약 작업 OFF를 확인한 다음 새 cron `0 13 * * *`(KST22시)을 켭니다. PUSH_MODE/ALLOW_LIVE_PUSH/비밀키 전환은 별도 최종 승인 범위입니다. 기존 작업이 실행 중이면 종료를 확인합니다. 새 D1 기준 미작성(개인 기록 포함 작성이면 제외)을 판단하고 날짜별 event_key로 중복을 막습니다. unknown timeout을 자동 재발송하지 않습니다. 오래된 시험/전환 전 queue는 검토 없이 발송하지 않습니다.

실제 자료 크기·원본 API/Drive 접근·전환 workflow가 없어 예상 중단 시간을 산출하지 않았습니다.

## PWA와 기존 푸시 구독

운영 SW에는 fetch/cache handler가 없고 Pages 공개 응답은 `Cache-Control:max-age=600`입니다. 열린 구형 HTML/HTTP 캐시가 남을 수 있으므로 source write freeze 없이 URL만 바꾸지 않습니다. 기존 `sw.js` 경로/등록 scope를 유지하고 `updateViaCache:none`으로 업데이트합니다. 강제 skipWaiting/reload, 전체 localStorage 삭제, 등록 unregister는 사용하지 않습니다. 대기 중 초안 보존을 확인하고 학생이 저장/복사한 뒤 옛 탭을 모두 닫고 재접속하도록 안내합니다.

실제 시험에서 legacy SW → 새 SW 대기/활성, 같은 경로/scope/manifest, 30일 token·사진 유지, logout, cache0, 핵심 GAS요청0을 확인했습니다. GitHub origin은 격리 브라우저에서 후보 asset을 가로채고 실제 Cloudflare API에 접속했습니다. 운영 Pages를 새 후보로 배포한 검증이나 이미 설치된 실물 PWA 검증은 아닙니다.

원래 Pages origin/scope와 **같은 VAPID 키 쌍**이면 브라우저의 기존 PushSubscription은 SW 업데이트로 유지할 수 있습니다. 기존 `ensureRealPushSubscribed`는 `getSubscription()`을 재사용한 뒤 새 D1의 인증 API로 재저장합니다. 앱을 다시 여는 것만으로 반드시 재등록되는지, iOS/Android 권한·endpoint 유효 여부는 실기에서 확인해야 합니다. `disable`/만료 endpoint 또는 VAPID 변경 시 사용자 허용과 재등록이 필요합니다. 시험 `.workers.dev` origin의 구독을 기존 Pages 구독으로 취급하지 않습니다.

Vercel 기존 `/api/send-push` GET405로 경로 존재를 확인했으나 bearer secret/VAPID 일치/실제 발송은 미검증입니다. 현재 transport payload는 원래 server의 subscriptions/title/body/tag/url 형식이며 정확한 badgeCount 계약과 만료 endpoint 응답은 서버 소스/비공개 설정 검토가 필요합니다. 시험 cron0/PUSH_MODE disabled, 가상 transport에서만 KST22시/중복/개인 기록/권한 철회/timeout을 검증했고 학생에게 발송하지 않았습니다.

## 신규 자료를 지키는 복구

판단 기준: 원본 불일치/계정・사진・권한 누출/중복 저장/저장 실패/로그인 장애/구형 GAS 쓰기가 계속되면 쓰기 재개를 중단합니다. 서비스가 이미 재개됐으면 **D1 장벽1 → Worker paused → 처리 중 작업 종료/상태 안정 → 현재 상태 전체 암호화 백업** 순서입니다. 신규 글・수정・삭제・현재 PIN hash・댓글/좋아요 관계・R2 원본/썸네일까지 담고 건수 외에 전체 값/관계/객체SHA256를 확인합니다. 초기 백업으로 덮어쓰거나 API URL만 GAS로 돌리지 않습니다. 백업과 복구 키는 별도 접근 제한 장소에 보관합니다. trial 도구가 만든 `.local` 키 파일은 가상 예행연습용이며 운영 키 보관 정책을 대신하지 않습니다.

기본 복구는 안정된 Worker/화면 버전으로 돌아가되 현재 D1/R2·현재 PIN을 유지합니다. schema 추가 index는 롤백할 필요가 없으며 DROP하지 않습니다. 신규 기능에 필요한 schema를 모르는 구버전에는 무조건 돌아가지 않습니다. 가상 로컬24테이블/223원본·썸네일의 AES256 백업을 별도 D1/R2에 복원하고 전체 값/관계/사진checksum을 대조했습니다. 원격 운영 code rollback과 실제 DB 복원은 미검증입니다. D1 손상이면 별도 DB/R2에 복원·최신 변화분 대조 후에만 binding을 바꿉니다.

**사용 가능한 복구 1 — 코드/설정만 복구, 최신 저장소 유지:** 검증한 같은 schema/인증 계약의 Worker・Pages 후보로 되돌리고 현재 D1/R2를 그대로 둡니다. 이때 student ID・현재 PIN・신규 기록・현재 세션 폐기를 유지합니다. 정확한 복구 Worker/Pages 산출물・API 설정・manifest/SW는 최종 승인 직전 고정해 비공개 보관합니다. 앱의 스키마를 모르는 구버전에는 돌아가지 않습니다. 동결을 끝내기 전에 새 PIN・신규 글/사진・권한・재시도를 검사하고 D1 장벽을 마지막에 풉니다.

**사용 가능한 복구 2 — 격리 복원:** D1/R2 손상 시 최신 전체 암호화 백업을 **새 별도 D1/R2**로 복원해 전 테이블・관계・SHA256 대조 후 binding을 바꿉니다. 원격 운영 binding 교체는 아직 실행하지 않았습니다. 최신 백업 이후 더 쓰였으면 손상 DB/R2도 읽기 전용 보존하고 그 이후 행/수정/삭제를 별도 검토해 반영합니다. 소실된 최신 데이터나 파일을 옛 백업만으로 재생성할 수는 없습니다. 확인할 수 없는 변화분이 있으면 쓰기를 재개하지 않고 읽기 전용으로 안내하며 원본들을 보관합니다. 오프라인 백업만으로 손실0을 보장하지 않습니다.

가상 격리 workerd에서 **전환 후 새 일기/사진・원본 글 수정/version・삭제 표시・댓글 부모・좋아요・PBKDF2-600000 새 PIN・재설정된 학생 session 폐기・다른 교사 session 유지**가 포함된 최신 상태를 암호화 복원해 전 테이블 일치를 확인했습니다. 동결 flag와 trigger도 복원하며 실제 row 복원 뒤 trigger를 켜므로 복원을 동결 장벽이 거절하지 않습니다. 객체 bytes와 DB 참조 checksum이 다르면 백업을 중단합니다. [예행연습 증거](검증/recovery-preparation-local-20261003.json).

실제 Cloudflare **가상 시험 서버**에서도 D1 장벽을 잠근 최신 상태를 읽기 전용으로 암호화 백업하고 새 **로컬 workerd**에 격리 복원했습니다. 25개 테이블/151개 원본・썸네일, 실제 재시도 저장으로 생긴 private 기록4개를 포함해 전체 행・관계・객체SHA256 일치. 원격 읽기는 한 번의 Worker batch가 아니라 D1 잠금・각 테이블 읽기・종료 시 전체 fingerprint/COUNT 대조로 일관성을 확인했습니다. [원격 백업/격리 복원 증거](검증/recovery-preparation-remote-20261003.json). 원격 운영 D1/R2 복원이나 실제 학생 자료 복원을 완료한 뜻은 아닙니다.

재현 명령은 `npm run recovery:rehearsal`(가상 격리 로컬), `npm run recovery:trial:rehearsal`(전용 원격 가상 시험을 일시 동결・암호화 백업・로컬 복원・재개)입니다. 후자는 현재 작업 브랜치・Cloudflare 인증・시험 리소스명/가상 계정 provenance를 확인하고 운영 DB를 거절합니다. 대용량 실제 자료의 백업/복원 소요・API 응답 한도・저장 비용은 원본 규모 확인 뒤 판단하며 작은 가상 결과를 그대로 적용하지 않습니다.

**완전 GAS 복귀는 현재 지원하지 않습니다.** 새 글/댓글/사진/삭제의 역방향 반입, PBKDF2 PIN 인증 호환이 없고 원래 GAS는 새 PBKDF2 PIN을 검증하지 못합니다. GAS로 주소만 돌리면 신규 기록과 현재 PIN을 쓸 수 없습니다. PIN 일괄 초기화・옛 PIN 강제 복원・원본 덮어쓰기는 하지 않습니다. 최종 승인 때 위의 최신 D1/R2 유지/격리 복원 방식과 한계를 명시적으로 제시합니다. 완전 GAS 복귀가 없다는 이유로 준비 가능한 작업을 중단하지 않습니다.
