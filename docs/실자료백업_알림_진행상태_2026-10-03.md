## 방금 작성한 일기와 현재 연결

사용자가 해당 일기를 **기존 운영 Google 시트에서 직접 확인**했고 비공개 일기가 아니라고 밝혔다. 그 기록은 원본에 보존돼 있다. 작업자가 최신 Google 셀을 직접 읽었다거나 새 백업에 이미 포함했다고 보고하지 않는다.

실제 공개 Pages는 `origin/main` HTML과 동일하고 GAS endpoint fingerprint도 같다. 저장과 교사 피드 `getRecentEntries`는 현재 GAS 경로다. Cloudflare 운영 Worker `okgu-diary-api`는 미배포이며 시험 D1은 가상 계정만 있다. 따라서 이 작업이 실제 기록을 Cloudflare와 GAS에 나눠 저장한 상태는 아니다. 기존 푸시는 Vercel 서버 연결이며, 알림 클릭 주소는 사용자 확인상 github.io이다. 사용자 기기의 실제 요청·설치된 SW 캐시는 직접 관측하지 않았다.

첨부한 서버 코드의 교사 피드 함수는 유효하지 않은 교사 세션이면 오류 대신 빈 배열을 반환하고, 저장시각 순으로 전체 기록을 페이지 나눈다. 이 함수 자체에는 피드 캐시나 `나만 보기` 제외 필터가 없다. 학생별 조회에는 해당 필터가 있으므로 두 API를 혼동하지 않는다. 현재 공개 앱의 `전체`/`오늘`/`비밀일기` 필터, 추가 페이지, 세션 상태 또는 현재 GAS 배포 코드가 원인인지 아직 확정하지 못했다. 운영 SW는 알림 클릭 때 기존 창에 메시지를 전달하고 navigate도 시도한다. 단순히 “알림 클릭이 재조회하지 않는다”고 단정하지 않는다.

교사가 작성 중인 내용을 보존한 뒤 **대시보드 → 피드 → 전체 → 새로고침**해 해당 기록과 기존 기록의 표시 여부를 확인하면 세션/필터/목록 문제를 좁힐 수 있다. 앱 저장소 삭제·학생 기록 수정은 요구하지 않는다. 해당 새 기록은 최신 원본 재수집 및 최종 변화분 대조에 반드시 포함한다.

## 알림 종류와 이번 수정

기존 코드/푸시 서버를 읽어 일기 작성·수정·삭제의 교사 알림, 게시판 삭제/좋아요·취소/댓글 작성·수정·삭제, 교사 일기 댓글의 학생 알림, 학생 답글의 교사 알림, 칭찬 승인 요청/승인 알림, 22시 미작성 알림을 유지했다. 활동 알림은 기존 이름·활동 문구를 사용하고 일기/댓글 본문은 payload에 넣지 않는다. 앱 내 알림은 원본도 댓글·칭찬에서 계산하므로 옛 알림 시트는 원문 archive로 보존한다. 구독 10개는 정상 endpoint/키/소유자·역할 검증 후 활성 테이블로 반입하고 기존 등록시각/활성 상태를 보존한다. 재반입으로 새로 비활성화한 구독을 되살리지 않는다.

Google OAuth의 Drive scope 자체는 쓰기 가능하지만 코드가 쓰는 대상은 새 백업 폴더/새 프로젝트 속성뿐이다. 실제 Google 실행은 미검증이다. 파일 열기 UI 요청은 queued이며 다운로드 가능한 첨부 전달이 확인된 것은 아니다. 현재는 **이미 성공했던 Google 백업 도구를 통한 새 ZIP**을 우선한다.

## 승인된 전환·중복 알림 방지·복구 순서

최신 수집/현재 배포 코드와 대응 확정 → 원본·후보 암호화 백업/대조 → 검토된 원본 동결 patch 배포/`OKGU_WRITE_PAUSED=yes` → GAS 실행 중 요청 종료 → 최종 원본 연속 캡처 안정 확인 → 별도 운영 D1/R2 최종 반입/전체 대조 → 기존 Pages main 루트 연결 전환 → 분리 확인 계정으로 이름/PIN·글/사진·ACL·교사 재설정 검증 → 쓰기 재개 → 알림 전환 순서다. 현재는 최신 자료 경로/운영 코드 확인 전이므로 동결하지 않는다.

동결 guard는 원본 `getSheet`도 막으므로 이때 일부 옛 조회도 잠시 불가할 수 있다. 새 UI는 저장 실패 시 본문/첨부/공개 범위를 유지하고 성공 뒤에만 완료를 표시한다. 원본 앱에서 이미 작성 중인 학생은 탭을 유지하고 본문 별도 복사/사진 원본 기기 보관을 안내한다. 브라우저 종료까지 초안 영구 저장을 보장하지 않는다. 동결 시간은 실제 최종 수집/반입 시간을 측정하기 전 추정하지 않는다.

알림은 **기존 GAS 예약 설정 기록 → 기존 예약 OFF 및 실행 중 발송 종료 확인 → 같은 KST 일자 발송 이력 대조 → 새 D1 cron `0 13 * * *` + dispatcher `* * * * *`/PUSH live ON** 순서다. GAS 동결 guard로 옛 직접 발송도 차단한다. 같은 날 옛 미작성 알림이 이미 발송됐으면 해당 날짜 새 event를 다시 발송하지 않는다. 옛 실행 결과가 불명확하면 그날 새 전체 미작성 발송은 켜지 않는다. 원본 코드는 삭제하지 않고 trigger 복구 정보만 비공개 보존한다. 복구 때도 두 서버가 동시에 ON이 되지 않게 한다.

실패 시 새 D1 공통 장벽부터 잠금 → Worker writes paused/PUSH disabled 및 cron OFF → 진행 중 작업 종료 → **전환 이후 새 기록·수정·현재 PIN·구독까지 포함한 최신 D1/R2 암호화 백업** → 호환 코드 수정/격리 자원 복원 → 전체 대조 → Pages 재연결/권한 확인 → 마지막에 장벽 해제한다. 사진 미참조 파일/원본 archive도 보존한다. 단순 GAS URL 복귀는 신규 자료·새 PIN을 잃으므로 하지 않는다. 완전 역방향 GAS 복원은 제공하지 않는다.

## PWA·실물 확인과 현재 결론

학생용 주소 `https://rlasksk030.github.io/okgu-diary-alarm-/`, manifest 식별 정보/start path/scope/SW 경로/공개 VAPID를 유지한다. 같은 origin·scope·키로 기존 push subscription을 재사용하고 새 D1에 등록한다. 기존 GAS session은 새 D1 session으로 옮기지 않으므로 실제 전환 뒤 같은 이름·PIN 재로그인이 필요하다. 앱 저장소 초기화/재설치를 기본 안내로 하지 않는다. 이번에는 운영 배포가 그대로이므로 학생 전체에 전환 재로그인을 요청하지 않는다.

실물 시험: [시험 앱](https://okgu-diary-pages-trial.rlasksk030.workers.dev/okgu-diary-alarm-/)에서 시험학생13/PIN `0042` + 30일 유지 → 가상 글/사진 저장·다시 열기 → 시험 PWA 홈 화면 추가·닫았다 열기/새로고침 → 로그아웃/다른 시험 계정에서 이전 자료가 안 보이는지 확인. 교사 재설정은 가상교사/0042 → 대시보드 → 학생 → 시험학생13 → PIN 재설정 → `0024`/확인 → 학생 기존 세션 만료·새 PIN·기존 기록 확인 → 끝나면 교사가 `0042`로 복원한다. 실제 운영 설치 PWA 업데이트는 전환 후 별도 확인이며 30일 실제 경과도 미검증이다.

선생님 휴대전화 **1건** 시험 승인은 유효하다. 기기를 확정한 후 제목 “옥구 다이어리 시험 알림”, 본문 “선생님 기기 알림 연결 확인입니다.”, 기존 앱 주소로만 1회 발송하고 서버 acceptance와 사용자 실물 수신/탭 화면 확인을 따로 기록한다. 새 운영 등록 이후 해당 기기를 특정할 수 있는지 확인하며 임의 학생/교사 endpoint를 선택하지 않는다. 전체 학생 시험 발송은 금지한다.

**시험 구현/실자료 격리 복원은 진행했지만 운영 전환은 완료하지 않았다.** 막힌 항목은 최신 운영 변화분, 현재 배포 코드/트리거 접근 확인이며 원본을 빈 데이터로 전환하지 않는다. main/운영 Pages/운영 알림/Supabase/유료 설정/원본은 이번 작업에서 변경하지 않았다.

## 재현 명령과 환경

Codex 클라우드에서 Node24/npm lockfile, Python/openpyxl3.1.5를 사용한다. 새 환경은 `npm ci`, `python3 -m pip install openpyxl==3.1.5`; 로컬 가상 앱은 `npm run build:local`, `npm run seed`, `npm start`(3020)다. `.local` 실제 source 폴더와 가상 fixture 폴더는 혼용하지 않는다.

```sh
npm run check
node --import tsx --test --test-isolation=none --test-reporter=tap tests/migration.test.mjs tests/push-photo.test.mjs tests/push-reliability.test.mjs tests/push-import.test.mjs tests/source-dispositions.test.mjs tests/source-export-v2.test.mjs
python3 scripts/audit-private-source.py .local/private-source/incoming-20261003
node --import tsx scripts/prepare-source-review.mjs "$OKGU_PRIVATE_RAW_PATH" "$OKGU_PRIVATE_SERVER_PATH"
node --import tsx scripts/rehearse-private-source.mjs .local/source-review/snapshot.candidate.private.json
node --use-env-proxy scripts/trial-notification-check.mjs
```

`OKGU_PRIVATE_RAW_PATH`는 이미 첨부한 원본 JSON의 비공개 로컬 경로, `OKGU_PRIVATE_SERVER_PATH`는 처음 받은 원문 파일 경로다. shell에서 값은 출력하지 않는다. review 입력은 현재 운영 코드 일치 확인 전 만들지 않는다. audit는 이번 ZIP 형식 v1용, 새 V2 exporter는 별도 정규화 경로를 사용한다.

실제 실행 결과: typecheck 통과, 위 source/notification 검증 23개 통과(동시 dispatcher가 예약된 재시도를 취소하지 않는 경합 검사 포함), 기존 회귀 파일별 실제 시험 API를 포함해 통과, 공개 시험 브라우저 16흐름 통과, 최종 시험 outbox 8흐름 통과, 실제 transport 발송 0. 전체 테스트 단일 합산은 setup hook 때문에 실패했으므로 파일별 실행으로 검증했고 그 실패를 성공으로 세지 않는다. 새 기능/속도 최적화/디자인 변경은 하지 않았다. 최근 승인된 속도 p95 3.64초는 재측정하지 않았다.

필수 비밀환경 이름은 기존 `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`; 런타임 운영 발송 시 `PUSH_SERVER_SECRET`(기존 확보값 재사용), 백업 시 `OKGU_BACKUP_KEY`(32bytes의 64hex, 비밀 설정)다. 소스/키/세션을 build vars·public config에 넣지 않는다. `.env.example`의 trial/production 구분과 안전한 CLI를 따른다. `LOGIN_KDF`는 내부 binding이며 브라우저 비밀값이 아니다. 새 사용자 로그인/클릭 없이 시험 배포했고 원격 trial vars/cron/private R2를 확인했다.
