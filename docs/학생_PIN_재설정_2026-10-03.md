기존 main `964985d3ff683617de18e89f71521f2c224d50f2`와 이전 작업 브랜치에는 **본인 PIN 변경만 있었고 교사의 학생 PIN 재설정은 없었습니다**. 이번에 교사 대시보드의 학생 카드에 ‘PIN 재설정’ 버튼과 기존 PIN 입력창 스타일을 재사용한 작은 창을 추가했습니다. 다른 디자인·기본 문구·메뉴·학생 흐름·본인 PIN 변경은 유지합니다.

1. 시험용 **가상교사**로 로그인합니다. 가상 계정의 공통 시험 PIN은 기존 안내값을 그대로 사용합니다.
2. 하단 **대시보드** → 상단 **학생**을 누릅니다.
3. 대상 학생 카드의 **PIN 재설정**을 누릅니다. 창 제목에 대상 학생 이름이 나옵니다.
4. **새 PIN (숫자 4자리)**와 **새 PIN 확인**에 같은 값을 입력하고 **저장**을 누릅니다. 앞자리 0은 문자 그대로 보존합니다.
5. 서버에서 저장한 뒤에만 ‘[학생 이름]의 PIN을 재설정했어요’가 나옵니다. **닫기**를 누릅니다.
6. 대상 학생은 기존 기기의 로그인 유지가 해제되므로 새 PIN으로 로그인합니다. PIN 원문은 조회할 수 없습니다.

이번 검증 대상 **시험학생09**는 검증 후 기존 공통 시험 PIN으로 복원했습니다. **시험학생01~13 / 가상교사**의 최종 접속 방법은 기존과 같습니다. 검증 중 생성한 다른 PIN은 메모리에만 보관했으며 로그·응답·문서·Git에 남기지 않았습니다. 시험 계정의 공통 가상 PIN 안내는 기존 [시험 실행 문서](Cloudflare_로그인과시험실행.md)를 참고합니다.

## 서버 처리와 자료 보호

`resetStudentPin`은 유효한 교사 세션을 확인하고, D1의 현재 교사 역할·활성 상태·학급, 대상의 학생 역할·활성 상태·같은 학급을 검사합니다. 이름·역할·학생 ID를 브라우저가 보내더라도 관리 권한의 근거로 삼지 않습니다. 대상은 D1의 고유 ID이며 교사 계정/다른 반/학생 요청/비로그인은 거절합니다. 해시 계산 중 권한이 변경되는 경우도 atomic batch의 조건문에서 다시 검사합니다.

같은 **PBKDF2-HMAC-SHA256 600,000회 + 새 무작위 salt**를 비공개 `LOGIN_KDF`에서 계산합니다. 계정 재생성 없이 credentials의 hash만 CAS로 변경하고 대상 학생의 sessions를 전부 삭제합니다. 단기 및 30일 토큰 모두 같은 세션 테이블을 사용합니다. D1 batch 중 실패하면 해시·영수증·세션 삭제가 함께 롤백됩니다. 기존 로그인도 현재 hash 조건으로 세션을 삽입하므로 변경 전 PIN 검증을 시작한 요청이 뒤늦게 새 세션을 발급하지 못합니다. 다른 사용자 세션과 자료 테이블은 변경하지 않습니다. 로그인 시도 제한/Origin/요청 헤더 보호도 유지합니다.

성공 요청은 UUID 영수증으로 재실행을 막습니다. 같은 요청의 재시도는 이전 성공을 반환하고 새 학생 세션을 다시 삭제하지 않습니다. 영수증 비교값은 **원문 교사 세션을 키로 한 HMAC**이며 숫자 4자리 PIN의 빠른 SHA 요약값을 저장하지 않습니다. D1에는 원문 세션을 저장하지 않습니다. 영수증 결과는 성공 여부·대상 ID/이름만 있고 PIN/해시는 없습니다. 별도 PIN 변경 로그/분석 이벤트를 추가하지 않았습니다. UI는 저장 중 입력/취소/저장을 잠그고, 실패 시 입력과 요청 UUID를 유지합니다. 로그아웃/계정 전환 시 창과 입력을 비웁니다.
