## 실제 자료를 받은 뒤 사용할 운영 배포 후보

학생 주소는 그대로 **https://rlasksk030.github.io/okgu-diary-alarm-/** 입니다. 계획한 운영 API는 `https://okgu-diary-api.rlasksk030.workers.dev`이며 **아직 배포되지 않았습니다.** 새 시험 접속 주소라고 안내하지 않습니다.

```sh
# 기존 작업 브랜치에서 실행. preview는 실제 DB 없이 오프라인 후보만 생성.
OKGU_PRODUCTION_API_ORIGIN=https://okgu-diary-api.rlasksk030.workers.dev \
  node scripts/prepare-production-candidate.mjs --preview
node scripts/verify-production-candidate.mjs
WRANGLER_SEND_METRICS=false XDG_CONFIG_HOME=/tmp/okgu-wrangler-config \
  node node_modules/wrangler/bin/wrangler.js deploy --dry-run \
  --config .local/production-candidate/wrangler.production.json \
  --outdir .local/production-candidate/compiled
```

`--preview`의 0 UUID는 실배포용이 아닙니다. 실제 원본 확보・백업・규모 검토 후 별도 운영 D1 `okgu-diary-production`과 비공개 R2 `okgu-diary-production-private`를 확인하고, 그 UUID를 `OKGU_PRODUCTION_D1_DATABASE_ID`로 안전하게 설정하여 **`--preview` 없이** 다시 생성합니다. 생성기는 UUID 형식・0 UUID・확보한 trial ID 재사용을 거부합니다. 이것은 **오프라인 후보 생성 도구**이며 remote 자원 이름/공개 설정/자료 비교를 검증하거나 실제 배포를 허용하는 도구가 아닙니다.

후보 위치:

- `.local/production-candidate/wrangler.production.json`: 운영 API 전용, ASSETS 없음, private LOGIN_KDF 유지, Pages CORS만 허용, `WRITE_MODE:paused`, push disabled, cron0, 진단/test/seed/비밀값 없음.
- `.local/production-candidate/pages/`: 현재 검증한 UI 파일과 동일한 복사본 및 새 `config.js`/`.nojekyll`. 운영 main의 기존 공개 VAPID 키를 읽어 사용하며 private 키는 포함하지 않음.
- `.local/production-candidate/compiled/`: Wrangler dry-run 산출물. 코드 후보이며 실제 자료 백업이 아님.

기존 Pages는 Actions 전용 artifact 방식이 아니라 **main 루트의 legacy 빌드**입니다. 자료 대조 완료 후 위 Pages 후보를 main 루트에 반영해야 합니다. 폴더 생성만으로 학생 앱이 바뀌지 않습니다. 이 시점의 main/Pages 변경은 이미 승인되어 있지만 실자료 대조 완료가 선행 조건입니다.

직접 검증: `npm run check` 통과, 신규 스크립트 `node --check` 통과, 후보 검증 통과, Wrangler `deploy --dry-run` exit0. UUID 미입력/잘못된 UUID/시험 DB 재사용/시험 API origin은 각각 거절했습니다. 기존 manifest의 이름/start_url/scope/icon을 main과 비교해 동일함을 확인했고 현재 index/rpc/fast-ui/student-pin/SW/icon은 후보와 byte 단위 동일합니다. 실제 운영 브라우저 로그인・저장 검증은 **전환 전이므로 미실행**입니다. 기존 7d3d3bf의 가상 66개 회귀/동결4흐름/원격 가상 백업→격리 로컬 복원 검증은 인계된 결과이며 이번에 다시 측정한 결과가 아닙니다.

GitHub API의 서버 배포 기록은 0건이므로 Vercel 화면에서 현재 commit/공개키 동일 여부만 확인합니다. 서버 코드・Bearer 값・저장소 링크를 다시 요구하지 않습니다.

실자료 `푸시구독`/`알림`은 기존 반입기의 archive-only 항목입니다. 원본을 받은 뒤 소유자 대응/중복/endpoint/key/원래 Pages origin을 검토해 active D1 구독 및 사용자 알림으로 대조 반입해야 합니다. 원본도 없이 가상 구독을 운영으로 복사하거나 자동으로 live를 켜지 않습니다. 운영 알림 전환 승인은 유효하므로 이 검토가 끝나면 old GAS 트리거 OFF/진행 중 실행 종료를 확인한 후 새 D1 기반 22시 KST cron/dispatch를 켭니다.

## 백업・복구와 미검증

**실제 원본 백업은 아직 만들지 못했습니다.** `.local/backups/` 등의 기존 파일은 가상 예행연습용입니다. owner가 만드는 비공개 Google 백업을 별도로 보관하고 전달받은 원본은 Git 제외 `.local/private-source/`에서만 읽습니다. 실제 이전/전환 후 백업은 접근 제한・AES256 암호화 상태로 보관하고 키를 별도 안전한 위치에 남겨야 합니다. 이 클라우드의 임시 `.local`만을 유일한 운영 백업으로 삼지 않습니다.

복구는 D1 공통 쓰기 장벽1→Worker paused→처리 중 쓰기 종료→현재 전체 D1/R2 암호화 백업/대조→동일 schema와 인증에 맞는 안정 코드 또는 별도 저장소 복원→신규 자료/현재 PIN/권한 확인→장벽 마지막 해제 순서입니다. 최신 PIN・새 글/사진・수정・삭제까지 보존합니다. GAS URL만 다시 지정하는 완전 복귀는 지원하지 않으며 사용자가 이 한계를 수용했습니다. 세부 절차는 [승인된 운영 실행안](운영전환_실행안_2026-10-03.md)에 있습니다.

현재 미검증은 실제 원본 내용/계정/PIN/날짜/공개 범위/사진 checksum/댓글 관계, 운영 반입/복원, 현재 GAS 배포・트리거・시간대, 실제 Pages 전환/CORS/로그인/쓰기/교사 PIN 재설정, 기설치 실물 휴대전화 PWA 업데이트, 실제 기기 알림 전달입니다. 별도 시험 서버나 모바일 viewport 검증을 이를 완료한 것으로 보고하지 않습니다.

학생에게는 **지금 새로고침/재로그인을 요구할 필요가 없습니다.** 운영 앱은 그대로입니다. 실제 전환 때는 작성 중 본문을 복사하고 원본 사진을 보관한 뒤 옛 탭을 닫고 같은 주소를 다시 열어 같은 이름/PIN으로 첫 로그인하게 안내합니다. GAS의 오래된 로그인 token은 새 D1 세션이 아니므로 첫 재로그인은 필요하지만 PIN 초기화는 하지 않습니다. 기존 PWA를 지우거나 전체 localStorage/푸시 구독을 일괄 삭제하지 않습니다.
